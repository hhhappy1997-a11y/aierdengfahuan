```
command_center/
├── commander/inbox/      总指挥投放命令（.json/.txt/.md/.cmd，写入后中枢扫到即派发）
├── commander/archive/    已处理命令归档
```

**回执格式**（AI 执行完自己写）：
```json
{"task_id":"<任务单里的 id>","ai":1,"status":"done","result":"执行结论"}
```

**任务单同步**：中枢派发的 `ai/N/inbox/task_*.json` 已由 HOST 各复制一份到真实工位 `Rank-N/调度任务单-R2.json`，所以 1-4 号 AI 在**自己工位里**就能拿到命令，不必进 command_center 找。

## 4. 继续下命令的方式（HOST 用）

最省事的是控制台 `http://127.0.0.1:8765/`，也可直接调 HTTP：

```bash
# 看状态
curl -s http://127.0.0.1:8765/api/state

# 投放命令：target = 1 / 2 / 3 / 4 / "1,3" / all / auto；priority = normal|high
curl -s -X POST http://127.0.0.1:8765/api/issue -H "Content-Type: application/json" \
  -d '{"target":"all","task":"<命令正文>","priority":"high"}'

# 配置（可改 space / demo / ai_names / ai_cmds / policy / poll_ms）
curl -s -X POST http://127.0.0.1:8765/api/config -H "Content-Type: application/json" -d '{"demo":false}'
```

其它接口：`/api/toggle`（暂停/恢复监测）、`/api/open_folder`（打开空间）、`/api/shutdown`（退出中枢）。
也可以直接把命令文件丢进 `commander/inbox/`，中枢 600ms 轮询会扫到并归档。
命令行参数：`--headless` 只跑后台、`--selftest` 复跑链路自检。

## 6. 仍待补的一环（真实闭环的关键）

`ai_cmds` 仍为空，**中枢不会自动拉起 1-4 号 AI 的会话**；任务单会躺在 `ai/N/inbox/` 等 AI 来读，`done=0` 是真实状态，不是失败。要变成自动闭环，二选一：

1. 给 `ai_cmds` 填各自启动命令（`{taskfile}` `{ai}` `{task}` 三个占位符），中枢派发时 `subprocess.Popen` 拉起；
2. 或由用户把 `00-唤醒指令-R2.md` 里对应那一段粘到各自的 AI 会话里，AI 读 `Rank-N/调度任务单-R2.json` 执行并写回执。

两种都不要同时跑，避免写同一批文件冲突。
