## 2. I-1 契约对齐核对表（不改接口、不私改契约）

| 契约条目 | 提供方 → 消费方 | 1 号本轮遵守情况 |
|---|---|---|
| I-1 `WorldState.get_flag(key, default)` / `set_flag(key, value)` | 3 → 1/2 | `chunk_streaming_r5.gd` 的 `_write_loaded_flag()` / `read_loaded_flag()` 只经 `has_method` 守卫后 `call("set_flag"/"get_flag")`，**不直接读写存档文件、不构造 SaveDelta** |
| I-1 `SaveDelta` 结构由 3 号定义 | 3 | 1 号不定义、不引用 `SaveDelta` |
| I-3 `SpawnRequest` 资源由 3 号传入、2 号消费 | 3 → 2 | 1 号不参与，本轮不涉及 |
| I-6 各模块 M0~M6 交付表 | 全体 → 主 AI | 见 `接口契约.md` §5（既有件，保留不改） |
| flag 键名 | — | 沿用 R4 口径 `chunk.<chunk_id>.loaded`（`FLAG_PREFIX="chunk."` + `FLAG_LOADED_SUFFIX=".loaded"`），1 号只收集/转交、不定义 schema；与 3 号存档键的最终一致性待裁决（见 §4） |

`chunk_streaming_r5.gd` 的 I-1 相关实现（既有件，保留不改）：

```gdscript
func _write_loaded_flag(chunk_id: String, value: bool) -> void:
    if _world_state == null or not _world_state.has_method("set_flag"):
        return
    _world_state.call("set_flag", _flag_key(chunk_id), value)

func read_loaded_flag(chunk_id: String, default_value: bool = false) -> bool:
    if _world_state == null or not _world_state.has_method("get_flag"):
        return default_value
    return bool(_world_state.call("get_flag", _flag_key(chunk_id), default_value))
```

> 降级设计：WorldState 单例缺失或缺少 `get_flag`/`set_flag` 方法时静默 no-op（不硬崩），符合契约「依赖降级矩阵」。

## 3. 接口级联调真跑（BUILD-R5.md §4 证据）

验证工程（系统临时目录，用完即删）为 Rank-3 提供最小契约替身，让 1 号的链路可跑：

- `scripts/world/world_state.gd`：`extends Node`，实提供 `get_flag(key, default)` / `set_flag(key, value)`，并带 `flags` 字典 + `set_calls`/`get_calls` 调用计数（**验证替身，不进交付清单**）。
- `scripts/core/game_events.gd`、`scripts/world/save_system.gd`：空 `extends Node` 替身，仅让 5 个 autoload 能加载。
- `scenes/world/chunks/chunk_limgrave_<x>_<y>.tscn`（`x,y ∈ {-2..2}`，25 个）：纯 `Node3D` 占位 chunk 场景，让 `load_threaded_request → get_status → get → instantiate` 有真实 `PackedScene` 可加载。

真跑 `res://scenes/r5_verify.tscn`（真实场景生命周期，autoload 由引擎正常加载）实际输出：

```
[r5_verify] desktop resident=9 wanted=9 loaded=9 frames=5
[r5_verify] mobile resident=4 wanted=4 loaded=4 root_children=13
[r5_verify] i1_bridge set_calls=9 get_calls=0 read_loaded_flag=true
[r5_verify] R5_PASS desktop_9=ok mobile_4=ok i1_bridge=ok chunks_instantiated=ok
```

链路逐环节核对（全部真跑、非静态推断）：

| 环节 | 证据 | 结论 |
|---|---|---|
| 占位 chunk 场景加载 | `loaded=9`（桌面）/ `loaded=4`（移动）、`root_children=13`（有实例入树） | `load_threaded_*` 完整时序 + 占位场景 `instantiate()` 入树成功 |
| flag 写入（I-1 set_flag） | `set_calls=9`（9 块各写一次 `chunk.<id>.loaded`） | 1 号只经 `WorldState.set_flag` 写，未碰存档 |
| flag 读回（I-1 get_flag） | `read_loaded_flag=true` | 1 号只经 `WorldState.get_flag` 读，读回 true，双向链路通 |
| 档位联动 | `9 → 4` 切换后 `wanted/loaded` 同步降为 4 | `quality_preset_*.tres` 的 `resident_chunk_count` 与运行时常驻集合一致 |

> `get_calls=0` 为驱动采样时点早于末次 `read_loaded_flag` 读取所致（详见 `BUILD-R5.md` §4），flag 读回 `true` 已证明 `get_flag` 生效，非缺陷。
