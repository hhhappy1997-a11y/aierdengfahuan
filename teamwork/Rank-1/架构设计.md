## 1. 渲染链路：SubViewport 低分辨率 → Nearest 放大

### 1.1 链路与节点职责

```
Main (Node)
└── SubViewportContainer        # Control，全屏 anchors_preset=15
    ├── stretch = true
    ├── stretch_shrink = 2      # 关键：容器 1280x720 / 2 => SubViewport 实际 640x360
    └── texture_filter = 0      # CanvasItem.TEXTURE_FILTER_NEAREST，放大时保持硬边像素
        └── SubViewport (640x360, own_world_3d=true, render_target_update_mode=ALWAYS)
            ├── Camera3D + SunLight(DirectionalLight3D) + WorldEnvironment
            ├── Ground (MeshInstance3D, 3D 网格地形)
            ├── Player (Node3D) → Hybrid2D3DAnimatedSprite
            ├── ChunkRoot (Node3D, 挂 chunk_streaming.gd)
            ├── WetReflection (Node3D)          # 湿地倒影，见 §2
            └── FXLayer (CanvasLayer, layer=10) # 光尘 / 全屏 FX，与 3D 同处低分辨率 viewport
```

**为什么用 `stretch_shrink` 而不是固定 `SubViewport.size`**：`SubViewportContainer.stretch = true` 时容器会把 SubViewport 尺寸设为 `容器尺寸 / stretch_shrink`，同时把渲染结果拉伸铺满容器。固定写死 `size` 会在窗口缩放后失效；用 `stretch_shrink = 2` 保证 1280×720 窗口下恒定 2× 整数倍放大，避免非整数缩放导致的像素抖动。窗口尺寸改变时按 `渲染档位` 重新计算 `stretch_shrink`（1 / 2 / 3），不允许出现 1.5× 这类非整数比。

**为什么 FX 层也放进 SubViewport**：主 viewport 是全分辨率，若把光尘、体积光叠加层放在主 viewport 的 CanvasLayer，它们会以平滑全分辨率渲染，与 3D 世界的像素颗粒对不上，直接破坏「像素精灵 vs 平滑景深」的对比。所有 2D 叠加 FX 必须挂在 SubViewport 内部的 `FXLayer`。

### 1.2 像素→米缩放公式

```
PIXELS_PER_METER = 32.0            # 32 px = 1 m
meters = pixels / 32.0
pixels = meters * 32.0
```

| 对象 | 像素尺寸 | 世界尺寸 |
|---|---|---|
| 主角 | 48 px 高 × 32 px 宽 | 1.5 m × 1.0 m |
| 杂兵 | 40 px 高 × 28 px 宽 | 1.25 m × 0.875 m |
| 1 格地砖 | 32 px | 1.0 m |
| chunk 边长 | 2048 px | 64 m |

该缩放由 `Hybrid2D3D-Renderer` GDExtension 的 `Hybrid2D3DSprite` / `Hybrid2D3DAnimatedSprite` 负责。**1 号不实现缩放、不实现 billboard、不实现锚定算法**，只在 `HybridSpriteRig`（见 `接口契约.md` I-4）里做一层薄封装并配置参数。

### 1.3 底部中心锚定（脚贴地）

- 精灵锚点固定在**底部中心**（`x = 图宽/2, y = 图高`），节点 `position.y` 直接等于脚下地面高度，不加半身高的补偿偏移。
- 3D 地面高度由 `Ground` 的碰撞体 / 高度查询给出；角色落地时 `position.y = 地面高度`，起伏地形用 0.1 m 步进插值，避免脚部像素上下跳帧。
- 翻滚、跳跃等动作帧**必须逐帧对齐脚底**，由 4 号 `import.json` 的 `anchor` 字段保证（I-5）；锚点不齐的帧在导入期拒绝加载并报出文件名，不在运行时补救。

### 1.4 自定义 AABB 防边缘剔除

Godot 用精灵平面原始 AABB 做视锥剔除；像素角色贴图有大量透明边，实际可见区域远小于角色包围盒，靠近屏幕边缘时会被整帧剔除（角色「闪没」）。

- 由扩展节点提供自定义 AABB，1 号在装配时设成以脚底为中心、覆盖完整动作最大外接框的固定盒：
  `AABB(Vector3(-0.75, 0.0, -0.75), Vector3(1.5, 1.8, 1.5))`。
- AABB 只随动作组切换（idle / roll / attack），不逐帧变化；逐帧变 AABB 会在剔除边界上抖动。
- 主角、Boss 用固定盒；大量杂兵可用同一预设盒实例化，不单独分配。

### 1.5 相机与像素对齐

- `Camera3D` 固定俯角约 30°、跟随玩家（1 号 M1 交付 `camera_rig.gd`：帧率无关指数平滑 `1 - exp(-rate*dt)`、死区、边界钳制、预留 `shake_offset` 钩子给 2 号）。
- 相机位移量化到 `1/32 m`（1 像素）整数步进再提交给引擎，消除亚像素抖动；量化只在渲染前做，物理与玩法坐标保持浮点连续。
- 透视 `fov = 40`，`near = 0.1`、`far = 400`。远景视差靠 3D 层深度生成（`BackdropFar / BackdropMid` 两组 unshaded 平面挂相机下、按 0.15 / 0.4 系数跟随），**不额外开第二个 viewport**，全部共享同一 640×360 像素栅格。

### 1.6 遮挡排序策略

| 层 | 实现 | 排序依据 |
|---|---|---|
| 3D 地形 / 建筑 | 不透明 `StandardMaterial3D` | z-buffer |
| 像素角色 / 道具 | `alpha_scissor`（`ALPHA_SCISSOR_THRESHOLD ≈ 0.5`），**不进透明队列** | z-buffer + 深度写入 |
| 湿地倒影 | 半透明、关闭深度写入 | 显式 `sorting_offset`，永远在地面之上、角色之下 |
| 光尘 / 体积光叠加 | `FXLayer` 2D 粒子，additive | CanvasLayer `layer = 10`，在 3D 之后 |
| 景深雾 | `Environment` 深度雾 + 体积雾 | 引擎内置，按深度 |

**要点**：像素角色绝不能用 alpha blend 参与 3D 透明排序，否则前后遮挡会随相机角度翻转。透明边缘一律 alpha scissor 硬切，这正是 HD-2D 需要保持的像素硬边。`Ground` 与角色材质都关 mipmaps，避免远处轮廓糊掉。

### 2.2 性能分级（1 号提供 `res://data/render/quality_profile_<档位>.tres`，运行时由 `SceneRouter` 切换）

| 档位 | 体积雾 | 光尘粒子上限 | 湿地倒影 | glow | 阴影图 | 体积雾步长 |
|---|---|---|---|---|---|---|
| Low（M0 默认） | 关，仅深度雾 0.008 | 0 | 关 | 关 | 1024 | — |

### 2.3 湿地倒影 shader 挂点（示意，非独立交付文件）

```glsl
// 挂在 WetReflection 下镜像精灵的 ShaderMaterial 上，canvas_item
shader_type canvas_item;
uniform float strength : hint_range(0.0, 1.0) = 0.35;
uniform float wobble   : hint_range(0.0, 8.0)  = 2.0;
void fragment() {
    vec2 uv = UV;
    uv.x += sin(uv.y * 40.0 + TIME * 1.5) * wobble * SCREEN_PIXEL_SIZE.x;
    vec4 c = texture(TEXTURE, uv);
    c.a *= strength * (1.0 - UV.y);   // 越远越淡
    COLOR = c;
}
```

## 3. chunk 流式加载状态机

### 3.1 分区与命名

- chunk 边长 `CHUNK_SIZE_M = 64.0`；玩家所在 chunk 为中心，`RADIUS = 1`，3×3 共 9 个常驻，覆盖 192 m × 192 m。
- id 严格 `chunk_<区域>_<x>_<y>`，例 `chunk_limgrave_0_1`；场景路径 `res://scenes/world/chunks/<chunk_id>.tscn`。
- 区域边界藏在**悬崖、升降机、地道**：这些位置由 3 号做视线阻断，1 号 `SceneRouter` 在触发体内做一次同步短加载（显示「开门 / 升降」动画遮罩），玩家不会看到空地。

### 3.2 三态去重

```
UNLOADED ──request──> LOADING ──instantiate──> LOADED
    ^                    │                       │
    │                    └── FAILED ────────────┘ (回到 UNLOADED，打日志不重试风暴)
    └──────── unload（延迟到期后）──────── UNLOADING ────┘
```

| 状态 | 含义 | 允许的转移 |
|---|---|---|
| `UNLOADED` | 不在内存 | → `LOADING` |
| `LOADING` | `load_threaded_request` 已发出，轮询中 | → `LOADED` / `UNLOADED`(失败) |
| `LOADED` | 实例已挂到 `ChunkRoot` | → `UNLOADING` |
| `UNLOADING` | 离开 3×3 但处于卸载延迟期 | → `LOADED`(玩家折返，取消卸载) / `UNLOADED`(到期) |

去重规则：`_states` 字典是唯一真相源；任何 `request` 前先查状态，`LOADING` 与 `LOADED` 一律跳过；同时在途请求数 `_active_loads` 受 `MAX_CONCURRENT_LOADS = 2` 限制。玩家在边界反复横跳时，靠 `UNLOAD_DELAY_SEC = 2.0` 的延迟卸载 + 折返取消，做到「不重复加载、不重复卸载」。

### 3.3 `ResourceLoader` 完整时序

| 步 | 调用 | 处理 |
|---|---|---|
| 1 | `ResourceLoader.load_threaded_request(path, "PackedScene", false)` | 返回非 `OK` 直接置 `UNLOADED` 并记失败；`use_sub_threads = false` 由引擎 WorkerThreadPool 统一调度，1 号不自己 `Thread.new()` |
| 2 | 每帧 `ResourceLoader.load_threaded_get_status(path, progress)` | `THREAD_LOAD_IN_PROGRESS` → 继续等；`THREAD_LOAD_FAILED` / `INVALID_RESOURCE` → 清状态、限流记日志；`THREAD_LOAD_LOADED` → 进入步 3 |
| 3 | `var res := ResourceLoader.load_threaded_get(path)` | 校验 `res is PackedScene`，否则按失败处理 |
| 4 | `var inst := res.instantiate()` → `ChunkRoot.add_child(inst)` | 挂树后调用实例可选的 `apply_world_flags(flags)`（见 §5），再 `chunk_loaded.emit(chunk_id)` |
| 5 | 离开 3×3 → 延迟 2 s → `queue_free()` | `chunk_unloaded.emit(chunk_id)`，状态回 `UNLOADED`，`_instances.erase(id)` |

补充：`load_threaded_get()` 只能在状态为 `THREAD_LOAD_LOADED` 后调用；提前调用会阻塞主线程，这正是 M2「帧尖峰」最常见的成因，已在 `chunk_streaming.gd` 的 `_poll_loads()` 里用状态判定杜绝。卸载用 `queue_free()`（帧尾安全释放），不在遍历中直接 `free()`。

### 3.4 与 I-1 的桥接

chunk 实例加载完成后，1 号只做「取 flag → 交给实例」：

```gdscript
var ws := get_node_or_null("/root/WorldState")     # 3 号提供，缺失时优雅降级
var flags := {}
if ws != null and ws.has_method("get_flag"):
    for key in chunk_instance.get_flag_keys():     # 由 3 号的 chunk 场景声明所需 key，1 号不定义 schema
        flags[key] = ws.get_flag(key, null)
chunk_instance.apply_world_flags(flags)
```

**1 号不读写存档文件、不构造 SaveDelta、不定义 flag 键名**（I-1）。POI 状态变化由 3 号订阅信号后调 `set_flag`。

## 4. 性能预算表

| 项 | 预算 / 取值 | 依据 |
|---|---|---|
| chunk 尺寸 | 64 m × 64 m（2048 px） | 32 px = 1 m；单 chunk 网格面数 ≤ 8k |
| 常驻 chunk 数 | 9（3×3），外加当前箱庭独立场景 1 | 总纲 3.2 |
| 在途并发加载 | ≤ 2；引擎内部子线程由 WorkerThreadPool 管理 | 超出会在低端机造成 IO 争抢 |
| 卸载延迟 | 2.0 s | 覆盖边界折返，避免抖动 |
| 低分辨率渲染目标 | 640 × 360（1280×720 / `stretch_shrink=2`） | 整数放大 |
| 目标帧时间 | 16.67 ms（60 FPS），p99 ≤ 20 ms | M2 验收基线 |
| 帧预算拆分 | 3D 地形 4 ms / 精灵 2 ms / 雾+glow 3 ms / 脚本 2 ms / 余量 5.67 ms | M2 超标时按此顺序砍 |
| 单 chunk 驻留内存 | ≤ 24 MB（网格 + 碰撞 + 贴图） | 9 × 24 = 216 MB |
| SubViewport 显存 | 640×360 RGBA8 ≈ 0.9 MB，双缓冲 < 2 MB | 可忽略 |
| 进程内存上限 | ≤ 1.5 GB（含 Godot 基线约 150 MB） | 留出 ComfyUI 本机并行余量 |
| 单帧绝对尖峰 | ≤ 33.3 ms（2 帧预算） | 超过即判 M2 不通过 |

### M2「性能监视器无 spike」验收口径（可量化，交给主 AI 汇总）

1. 场景：3 个相邻 chunk（`chunk_limgrave_0_0/1_0/2_0`），在边界之间往返走各 2 次，连续 ≥ 5 分钟。
2. 采集：`F3` 打开 1 号 M2 交付的性能 HUD，读取 `Performance.TIME_PROCESS`、`Performance.TIME_PHYSICS_PROCESS`、`Performance.MEMORY_STATIC`、`Performance.RENDER_TOTAL_DRAW_CALLS_IN_FRAME`。
3. 通过条件（全部满足）：
   - 帧时间 p99 ≤ 20 ms，最大单帧 ≤ 33.3 ms；
   - `chunk_loaded` 对每个 chunk_id **只发一次**（折返不触发第二次），用信号计数在 HUD 里显示；
   - `MEMORY_STATIC` 回到起点时与基线差 ≤ 10%，无单调增长（无泄漏）；
   - 加载瞬间不掉帧（`load_threaded_get` 只在 LOADED 状态调用）。
4. 目标硬件待用户确认；未确认前以「本机集成显卡 + Low 档」为默认验收环境。

## 5. 存档对接（I-1）

- 唯一入口：`WorldState.get_flag(key, default)` / `WorldState.set_flag(key, value)`（3 号定义实现与 `SaveDelta` 结构）。
- 1 号代码中**不出现** `FileAccess`、`ConfigFile`、`user://`、`SaveDelta` 构造、`JSON.stringify` 落盘。
- flag 键名遵守契约三段式 `<模块>.<对象>.<状态>`。1 号只**消费**，不定义；建议形状 `world.chunk_limgrave_0_0.chest_01_opened`，具体 schema 由 3 号定，已列为待裁决项。
- 缺 `WorldState` 单例（3 号尚未交付）时，`chunk_streaming.gd` 走 `get_node_or_null` 降级为空 flags 并 `push_warning`，不阻塞 M0/M1 独立试玩。

## 6. 密度原则落地（每 30 秒路程 1 个 POI）

- 玩家基准速度 4.5 m/s → 30 秒 = 135 m ≈ 2.1 个 chunk 边长。
- 落地为**硬约束而非口号**：每个 64 m chunk 的场景元数据 `res://data/chunks/<chunk_id>.tres` 必填 `poi_min_count = 1`、`poi_max_spacing_m = 64.0`；M1 起 `SceneRouter` 加载 chunk 时校验，缺 POI 的 chunk 在编辑器输出 `[density] chunk_xxx 未达密度下限` 警告。
- 1 号只提供字段与校验钩子，POI 具体摆放（赐福、地牢入口、精英、NPC）属 3 号内容。
- 视线阻断处（悬崖 / 升降机 / 地道）同时充当「隐藏加载边界」与「POI 节奏点」，一举两得；隐藏墙按总纲不给任何提示。
- M2 的 3 个 chunk 每个至少放 1 个占位 POI（程序化 `_draw()` 占位即可），保证验收样本本身符合密度原则。

## 7. 分阶段工程侧交付摘要

完整 M0~M6 表见 `接口契约.md` 第 5 节。工程侧主线：M0 打通「低分辨率链路 + 脚贴地 + 1 个 chunk」→ M1 补「3D 庭院碰撞 + 相机 + FX 挂点 + I-4 接口」→ M2 补「3×3 流式加载 + 性能 HUD」，之后 M3~M6 只提供场景切换、flag 桥接与热替换钩子，不再新增渲染能力。
