# 00-群组通信协议（群组层补充）

## 0. 定位与真源

- 本协议是 `00-协作契约.md` 的**第 9 节补充**，只定义「群组通信」这一件事。需求真源仍是 `00-项目总纲.md`，硬约束真源仍是 `00-协作契约.md`；本协议不重复、不覆盖契约条款。
- 群名：`HD2D-5AI`（企业微信群显示名：艾尔登法环 · 5-AI 协作群）。
- 成员：`HOST`（主 AI）、`Rank-1` ~ `Rank-4`（4 路任务 AI）、`OWNER`（用户）。
- **唯一真源**：`00-群聊总线.md` 是群组消息的唯一真源。企业微信群只是**人机投影通道**，不是第二份消息库；群内聊天记录不得当作需求或决议。
- 任务 AI 不是企业微信账号，无法作为群成员被拉入。它们通过各自任务会话读写 `00-群聊总线.md` 接入群组；企微群是给人看、给人插话、给主 AI 推送摘要用的。

## 1. 什么算「在群里沟通」

各路 AI 在**自己的任务会话里**向总线追加消息 = 在群里发言；开工时读一次总线 = 查看群消息。不存在、也不需要跨任务的会话互通（WorkBuddy 每个对话是独立任务，各自维护独立上下文）。

## 2. 消息格式（追加到 `00-群聊总线.md` 末尾，只增不改）

```
## MSG-<YYYYMMDD-HHMM>-<FROM> · <YYYY-MM-DD HH:MM> · <FROM> → <TO>
- TYPE: <接口变更|交付完成|阻塞求助|裁决请求|裁决|同步|通知>
- REF: <I-1~I-6 / M0~M6 / 文件路径 / ->
- BODY: <一句话正文>
- STATUS: <OPEN|ACK|CLOSED|VOID>
```

字段规则：

- `TO` ∈ `ALL` / `HOST` / `OWNER` / `Rank-N`，多方用逗号分隔。
- 编号自带「时间戳 + 发件人」，4 路并发追加也不会撞号；**禁止抢号、禁止修改他人条目**。
- 作废消息用新追加一条 `STATUS=VOID` 并在 `REF` 指向原编号，不得删除或改写原条目。
- 机密（密码、key、令牌）不进总线、不进企微群。

## 3. 事件驱动读写（不轮询、不刺探）

- 每路 AI **仅在自己被唤醒开工时读一次**总线，读到最后一条即可；不定时巡检、不写探针脚本、不扫目录核实他人工位。
- **必须发言**的四类事件：
  1. 接口 I-1~I-6 有变更；
  2. 本路里程碑（M0~M6）交付完成；
  3. 被阻塞、需要他路配合；
  4. 收到 `TO` 含自己且 `STATUS=OPEN` 的消息后给出回应（回应后另追加一条 `TYPE=通知` 说明该编号已 CLOSED，不改原文）。
- 除此之外**不发闲聊**，不为了「报进度」反复刷屏。
- 只有用户明确说「刺探 / 量一下 / 补读数 / 巡检」时，才做一次只读现场确认，仍按契约第 5 节执行。

## 4. 企业微信群桥接规则

- **总线 → 群**：只有用户说「同步到群」时，主 AI 把上次同步游标之后的新消息汇总成一条文本发到企微群，并在总线追加一条 `TYPE=同步` 记录新游标。**不自动定时同步、不常驻监听、不建轮询任务。**
- **群 → 总线**：用户在企微群里插话，由主 AI 在用户明确要求时导入总线，`FROM=OWNER`、`TYPE=通知`、`REF=WECOM` 并注明来源；群里的讨论本身不产生决议。
- 群里只发摘要与结论，不发整份文档；需要留档的内容一律落总线或工位文件。
- 桥接失败（网络 / 授权 / 策略）如实报告一次即停，不重试、不改用本地副本伪装同步成功。

## 5. 冲突与裁决

- 接口争议以 `00-协作契约.md` 的 I-1~I-6 为唯一准绳。
- 群内讨论不构成决议。裁决必须由 `HOST` 在总线追加 `TYPE=裁决` 消息，写明依据与结论，各路据此执行。
- 沿用既定分工：1~4 路由用户自行安排各自的 AI 执行，主 AI 不代跑；主 AI 只负责总纲、契约、派单、总线维护与 4 路产出齐备后的汇总与冲突裁决。

## 6. 禁止项

- 不新建第二份群聊 / 消息文件（SSOT）。
- 不删除、不改写、不重排总线历史条目。
- 不引入付费素材或外部生成服务；本项目维持零外部依赖。
- 不为同步写常驻进程、定时轮询或探针脚本。
