# 箱庭地牢模板：钟窖 `dungeon_01_bellvault`（M3）

> 一份**可直接照着搭**的独立地牢规格：多层立体结构 + 1 条单向门捷径 + 1 赐福 + 1 精英敌人。
> 归属 3 号（关卡内容 / 交互 / Delta）。渲染实现与场景树骨架 → 1 号；精英战斗数值与 AI → 2 号；美术 → 4 号。
> 配套：`存档与flag规范.md`（Delta / flag）、`RPG系统设计.md`（交互件 / 赐福 / 门规则）、`接口契约.md`（`SpawnRequest` 字段集）。

---

## 0. 一句话与边界

地表 `grace_limgrave_gatefront` 西北 40 m 的**断崖地道**后，是一座向下挖了三层的废弃钟窖。玩家从 B1 进、逐层下沉到 B3 井底，**只能从 B3 侧打开单向门**，一步回到 B1 赐福厅——这就是法环式「捷径」的魂。

| 项 | 值 |
|---|---|
| 地牢 id | `dungeon_01_bellvault` |
| 场景路径 | `res://scenes/dungeons/Bellvault.tscn`（单场景，三层用 Y 标高，不做层间场景切换） |
| 局部坐标 | 入口为原点 `(0, 0, 0)`；B1 `y=0`、B2 `y=-6`、B3 `y=-12`（层高 6 m） |
| 占地 | 约 `34 m × 26 m`（三层叠合），总可走路径约 `360 m` |
| 楼层数 | 3（B1 / B2 / B3） |
| 赐福 | **1 个**：`grace_bellvault_entry`（B1 赐福厅）。井底赐福 `grace_bellvault_deep` 属 M6 增量，M3 不放 |
| 精英敌人 | **1 个**：`elite_01_bell_warden`（B2 钟厅） |
| 单向门捷径 | **1 条**：`world.bellvault_shortcut_door_01.unlocked`（B3 井底 → B1 赐福厅） |
| 隐藏墙 | 1 面（B2 侧廊），**零提示** |
| 短加载 | 只在进 / 出地牢各 1 次，层间不加载 |
| 密度 | 任意连续 30 秒步行窗口内 ≥ 1 个 POI，最长空窗 26 s |

## 3. 单向门 / 捷径规则（本模板实例）

| 项 | 值 |
|---|---|
| door id | `bellvault_shortcut_door_01` |
| `InteractableSpec.kind` | `one_way_door` |
| `open_side` | `b3_side`（玩家必须位于 `room_b3_02_shortcut_door` 一侧） |
| 反侧表现 | B1 侧 `room_b1_02_grace_hall` 靠近时**不显示提示图标**、按交互键无响应、门体无高亮 |
| 开启写入 | `set_flag("world.bellvault_shortcut_door_01.unlocked", true)` + `set_flag("dungeon.bellvault.shortcut_opened", true)`（同批，一次 `seq` 合并窗口） |
| 开启后 | 变普通双向通道，**不能重新锁上**，flag 单调 |
| `delta_checkpoint` | `true`，`reason = "shortcut_opened"`，强制落盘 |
| 加载 | 门在 `Bellvault.tscn` 内部，不跨 chunk 边界；短加载后读 flag 重建门体旋转角 |
| 赐福网络 | M3：只写 `grace.bellvault_entry.visited`；**M6 增量**：`dungeon.bellvault.shortcut_opened` 作为 `grace_bellvault_deep` 边的 `requires_flags`（井底赐福 M3 不放置） |
| 隐藏墙差异 | 隐藏墙 `prompt_enabled = false`；单向门反侧只是"无响应"，**仍可看见门体**，两者不可混为一谈 |

**单向门的判定不靠碰撞体朝向**，靠 `InteractableSpec.open_side` + 玩家所在房间 id（`room_b3_02`）双条件校验；1 号做碰撞时只需要一个 `Area3D`，不需要在门两侧各放一个触发器。

## 4. 加载边界与短加载

### 4.1 边界位置（藏在视线阻断处）

| 边界 | 位置 | 遮挡物 | 触发 |
|---|---|---|---|
| 地表 → 地牢 | `room_b1_01_gate_tunnel` 拐弯处 | 断崖岩壁 + 地道转角 | 玩家进入地道 Area3D 且转过拐角 |
| 地牢 → 地表 | 同上，反向 | 同上 | 赐福菜单「离开地牢」或地道出口 Area3D |
| 层间 B1↔B2↔B3 | **无边界** | — | 三层在同一 `.tscn`，用 Y 标高 + 相机跟随，不加载 |

### 4.2 短加载时序（与 1 号 `ChunkManager` 协同）

```
1 玩家越过地道拐角 → 3 号发 dungeon_transition_requested("dungeon_01_bellvault", "enter")
2 1 号 ChunkManager 暂停地表 3x3 流式加载（不再 load/unload 地表 chunk）
3 3 号强制落盘 reason="dungeon_enter"（《存档与flag规范》§4.8）
4 淡出 0.25 s → 显示短加载遮罩（金线深蓝 UI，1 号渲染）
5 ResourceLoader.load_threaded_request("res://scenes/dungeons/Bellvault.tscn")
6 主线程轮询 load_threaded_get_status()；THREAD_LOAD_LOADED → load_threaded_get()
7 实例化 → 按 SaveDelta 重建交互物状态（只读 flag，见 §5）
8 玩家落到 spawn_marker_b1_entry（从地表来）或 spawn_marker_b1_grace（传送 / 捷径来）
9 淡入 0.25 s → 输入解锁 → 发 dungeon_entered(dungeon_id)
```

- **短加载口径**：目标从步骤 4 到步骤 9 **≤ 0.8 s**（含淡入淡出 0.5 s，实际加载预算 0.3 s）；遮罩至少显示 0.5 s 避免闪屏。
- 层间移动**零加载**：不做 `load_threaded_request`，靠 3D 网格遮挡 + 相机裁剪，玩家感知为连续空间。
- 地牢内 `ChunkManager` 保持暂停；退出时恢复并把玩家所在 chunk 重新设为 `chunk_limgrave_0_1`。
- 传送进地牢（M6）跳过步骤 2 的暂停判断，直接由 `SceneRouter` 走同一条 4~9 流程。

> 跨模块依赖：步骤 2「暂停 chunk 加载」与步骤 6 的 `ResourceLoader` 调用属 1 号职责，3 号只发 `dungeon_transition_requested` 信号并约定参数；具体信号承载节点见 `README.md` 待裁决 A6。

## 6. 精英敌人 `SpawnRequest`（I-3 权威字段集，2 号消费）

> 完整字段定义见 `接口契约.md` §3。下面给出本模板实例，可直接存为 `res://data/spawns/spawn_bellvault_elite_01.tres`。

```
}
```

> `patrol_route` 声明为非类型化 `Array`，元素为 `Vector3`；Godot 4 的 `.tres` 解析器直接支持 `[Vector3(...), ...]` 字面量。数值不在此处调手感，改 `EnemyData` 数据表即可（总纲 3.4「改数值不改代码」）。

**击杀链路**：2 号发 `enemy_defeated("elite_01_bell_warden")` → 3 号 `SaveDeltaWriter` 订阅 → 查 `SpawnRequest.defeated_flag` → `set_flag(..., true)` → 强制落盘 `reason="enemy_defeated"` → 宝箱 `bellvault_chest_01` 的守护解除。2 号**不写** flag（避免双写）。

## 7. 密度与验收口径

### 7.1 密度定义

**POI** = 下列任一可见/可交互对象：赐福、宝箱、精英敌人、普通敌人组、NPC、拾取物、单向门、升降机、隐藏墙（隐藏墙只计入**内容密度**，不计入可见密度）、具有辨识度的地标（断桥、铁链坡道、水池）。纯走廊不算。

**30 秒口径**：以 1 号 M1 玩家基础移速 `3.5 m/s` 为基准，30 s ≈ `105 m`。统计方法为「在完整试玩录屏里，取任意起点连续 30 s 的滑动窗口，窗口内必须至少出现 1 个 POI（含窗口起止点所在房间）」。本模板最长空窗 **26 s**，达标。

> 移速基准 `3.5 m/s` 是 2 号 M1 玩家动作的实际值；若 2 号最终数值不同，本表「步行 s」需按 `距离 / 实际移速` 重算，密度结论须复核 → 列入 `README.md` 待裁决 A7。
