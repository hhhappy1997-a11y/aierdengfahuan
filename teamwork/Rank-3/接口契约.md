## 1. I-1 —— `WorldState` 与 `SaveDelta` 对外契约（权威）

### 1.1 `WorldState` 精确签名

```gdscript
# Autoload 单例名：WorldState
# 脚本路径：res://autoload/world_state.gd （1 号负责在 project.godot 注册，3 号实现）

func get_flag(key: String, default: Variant = null) -> Variant   # 纯读、无副作用
func set_flag(key: String, value: Variant) -> void               # 幂等、变化时发信号并入 Delta
```

| 约束 | 内容 |
|---|---|
| 允许调用方 | 1 号、2 号、3 号 |
| 允许方法 | **仅上述两个** |
| `key` | 严格三段式 `^(world\|quest\|combat\|grace\|dungeon)\.[a-z0-9_]+\.[a-z0-9_]+$` |
| `value` | 仅 `bool / int / float / String`；越界 `push_error` 并忽略写入 |
| `get_flag` | 不创建 key、不发信号、不写盘、返回值拷贝；未命中返回 `default` |
| `set_flag` | 同 key 同值重复调用不增加 `seq`、不发 `flag_changed`；变化时顺序为「更新内存 → 发信号 → 入队 Delta → `seq += 1`」；**从不在调用内同步落盘** |
| 可选订阅 | `flag_changed(key, old_value, new_value)`、`delta_committed(seq, reason)`（只读，订阅回调里禁止再 `set_flag` 造成递归） |
| 禁止 | 直接读写 `user://saves/`、解析 / 构造 SaveDelta、访问 `WorldState._flags` / `_delta` / `save()` / `load()` / `_commit_delta()` 等内部成员 |

> 3 号内部方法（`_commit_delta` / `_apply_snapshot` / `_begin_grace_rest` / `_register_baseline` / `_validate_flag_key`）签名可随版本变化，**1 / 2 号不得依赖**。

### 1.2 `SaveDelta` 顶层契约

```json
{
  "schema_version": 3,
  "slot": "slot_01",
  "seq": 1842,
  "baseline": { "manifest": "res://data/world_baseline.tres", "manifest_hash": "sha256:...", "baseline_version": 1, "resource_ids": [] },
  "flags": { "grace.limgrave_gatefront.lit": true },
  "quests": { "quest_01_bell_of_return": { "stage_id": "stage_02_return", "flags": {} } },
  "inventory": { "grants": {}, "consumed": {} },
  "spawns": { "defeated": [], "epoch": 0 },
  "removals": [],
  "meta": { "playtime_seconds": 0, "area_id": "", "last_grace_id": "", "written_at_unix": 0, "game_version": "", "last_commit_reason": "" }
}
```

| 对 1 / 2 号的契约点 | 说明 |
|---|---|
| **不可见** | 1 / 2 号不需要知道 SaveDelta 存在，更不得读写其文件 |
| **基线 + 变化** | Resource 基线只读；`flags` 只含相对基线的变化值 |
| **门 / 隐藏墙 / 升降机** | 全部收敛进 `flags`，无 `doors` / `lifts` / `chests` 等顶层字段 |
| **单槽路径** | `user://saves/slot_01/delta.json`（+ `.log` / `.bak` / `.tmp`），`res://` 不写 |
| **回放与冲突** | 按 `seq` 升序，同 key 大 `seq` 胜；`removals` 优先；类型以 flag 登记表为准 |
| **原子写** | `delta.json.tmp` → `flush()` → `rename` → 成功后更新 `.bak` |
| **迁移链** | `1 → 2 → 3` 逐级，禁止跳级；未知更高版本拒绝加载 |
| **写入时机** | 赐福点亮 / 休息、传送、地牢进出、Boss 与精英击杀、拾取、任务阶段推进、退出 = **强制同步**；其余 flag 0.5 s 合并窗口 |
| **崩溃恢复** | 最多丢 0.5 s 内非关键 flag；上述强制点零丢失 |

完整 JSON 示例、回放 9 步、迁移表、验收口径见 `存档与flag规范.md` §4 / §6。

## 2. I-2 —— 订阅 2 号击杀信号的方式

### 2.1 契约内容

| 项 | 值 |
|---|---|
| 提供方 | 2 号 |
| 信号 | `enemy_defeated(enemy_id: String)`、`boss_defeated(boss_id: String)` |
| 参数 | **单个 String**（数据表 id，如 `elite_01_bell_warden` / `boss_01_margit`）；不是 StringName、不是 Dictionary、不带第二参数 |
| 消费方 | 3 号 `SaveDeltaWriter`（`res://scripts/rpg/save_delta_writer.gd`） |
| 3 号写入 | `combat.<对象>.defeated = true`（三段式），并按 `respawn_policy` 决定是否进 `spawns.defeated` |
| 2 号禁止 | 不写 `combat.*` flag、不碰 SaveDelta（避免双写导致 `seq` 重复） |

### 2.2 连接发现方式（3 号侧实现，不要求 2 号改接口）

```gdscript
# res://scripts/rpg/save_delta_writer.gd —— 3 号内部实现示例
extends Node

func _ready() -> void:
    var bus: Node = get_tree().get_first_node_in_group("combat_signal_bus")
    if bus == null:
        bus = get_node_or_null("/root/GameEvents")   # 兼容 1 号 autoload 命名
    if bus == null:
        push_error("I-2: 未找到击杀信号总线，存档无法记录击杀")
        return
    if bus.has_signal("enemy_defeated"):
        bus.enemy_defeated.connect(_on_enemy_defeated)
    if bus.has_signal("boss_defeated"):
        bus.boss_defeated.connect(_on_boss_defeated)

func _on_enemy_defeated(enemy_id: String) -> void:
    var req: SpawnRequest = SpawnRegistry.find_by_enemy_id(enemy_id)
    var flag_key: String = String(req.defeated_flag) if req != null else ""
    if flag_key.is_empty():
        flag_key = "combat.%s.defeated" % enemy_id
    WorldState.set_flag(flag_key, true)
    if req != null and String(req.respawn_policy) != "never":
        SaveDeltaWriter.mark_respawnable(enemy_id)      # 进 spawns.defeated
    WorldState._commit_delta("enemy_defeated")          # 3 号内部强制落盘

func _on_boss_defeated(boss_id: String) -> void:
    WorldState.set_flag("combat.%s.defeated" % boss_id, true)
    WorldState.set_flag("combat.%s.phase_two_ready" % boss_id, false)
    GraceNetwork.unlock_by_flag("combat.%s.defeated" % boss_id)  # 例：解锁史东薇尔城门
    WorldState._commit_delta("boss_defeated")
```

> ⚠️ 上例中的 `WorldState._commit_delta()` 是 **3 号内部方法**，仅用于说明 3 号链路；**1 / 2 号不得调用**（I-1 只允许 `get_flag / set_flag`）。

### 2.3 处理规则

1. **幂等**：同一 `enemy_id` 重复发信号 → `set_flag` 幂等，`seq` 不重复增长。
2. **精英 / Boss 不刷新**：`respawn_policy = "never"`，`combat.*.defeated` 永久保留，不进 `spawns.defeated` 清空列表。
3. **普通敌人**：`on_grace_rest` 时由 `grace.network.last_rest_epoch` 递增清空 `spawns.defeated` 并把 `combat.<id>.encounter_started` 置回 `false`。
4. **落盘**：击杀一律强制同步 `reason = "enemy_defeated" / "boss_defeated"`。
5. **找不到 SpawnRequest**：用 `"combat.%s.defeated" % enemy_id` 兜底，并 `push_warning` 便于对账。

> 「信号承载主体」在契约中未指定，3 号采用「节点组 `combat_signal_bus` 优先 + `/root/GameEvents` 兼容」的发现顺序，**不要求 2 号改代码**。最终统一到哪个承载体见 `README.md` 待裁决 A2。

## 3. I-3 —— `SpawnRequest` 完整字段集（3 号定义，2 号消费）

脚本路径：`res://scripts/rpg/spawn_request.gd`，`class_name SpawnRequest extends Resource`。实例见 `箱庭地牢模板.md` §6（可直接使用的 `.tres` 片段）。

| # | 字段 | 类型 | 默认值 | 取值范围 / 格式 | 语义 | 2 号消费规则 |
|---|---|---|---|---|---|---|
| 1 | `request_id` | String | `""` | `spawn_<slug>` | 请求唯一 id，用于对账与日志 | 只读，作日志键 |
| 2 | `enemy_id` | String | `""` | `<类别>_<序号>_<slug>` | 2 号 `EnemyData` / `BossData` 数据表 id | **必须**据此查表；查不到则 `push_error` 不生成 |
| 3 | `spawn_point_id` | String | `""` | Marker3D 节点名 | 生成挂点 | 由 1 号场景提供，2 号只按名取位置 |
| 4 | `position` | Vector3 | `Vector3.ZERO` | Godot 世界坐标 | 生成坐标兜底（`spawn_point_id` 找不到时使用） | 只用于摆位，不改战斗数值 |
| 5 | `facing_degrees` | float | `0.0` | `[0, 360)` | 初始朝向（绕 Y 轴） | 只用于摆位 |
| 6 | `level` | int | `1` | `>= 1` | 敌人等级，交 2 号查表 | 只读，不改数据表 |
| 7 | `hp_override` | int | `-1` | `-1` 或 `>= 1` | `-1` = 用数据表 HP | `>= 0` 时覆盖本次生成 HP；**不改数据表** |
| 8 | `stance_override` | float | `-1.0` | `-1.0` 或 `>= 0.0` | `-1.0` = 用数据表韧性 | 同上 |
| 9 | `aggro_radius` | float | `8.0` | `>= 0.0` | 进入即接战半径 | 覆盖 AI 感知半径（不改数据表） |
| 10 | `leash_radius` | float | `16.0` | `>= aggro_radius` | 脱战回位半径（含滞回） | 覆盖 AI 丢失半径 |
| 11 | `respawn_policy` | String | `"on_grace_rest"` | `never` / `on_grace_rest` / `on_area_reload` | 刷新策略 | 2 号不自行刷新；由 3 号按此字段写 Delta |
| 12 | `defeated_flag` | String | `""` | 三段式 `combat.<对象>.defeated` | 击杀后 3 号要写的 flag | **2 号不写此 flag**；空串时 3 号用 id 兜底 |
| 13 | `loot_table_id` | String | `""` | `loot_<序号>_<slug>` | 掉落表 id | 2 号按表掉落；3 号不结算数值 |
| 14 | `patrol_route` | Array | `[]` | 元素 `Vector3` | 巡逻点，空数组 = 原地待机 | 只读 |
| 15 | `is_boss` | bool | `false` | — | 是否 Boss（血条 / 二阶段） | 只读 |
| 16 | `spawn_group_id` | String | `""` | `group_<slug>` | 同组敌人共享重置 / 计数 | 只读 |
| 17 | `metadata` | Dictionary | `{}` | 任意标量键值 | 非战斗元数据（房间 id、镜头、音频开关） | 只读；**不得**往里塞战斗数值 |

**2 号消费硬约束**

1. 全部战斗数值（HP、削韧、招式倍率、异常积累、阶段阈值）**只从 2 号自己的数据表取**；`SpawnRequest` 只提供上表 7~10 项覆盖位，不改数据表。
2. **不得**新增、删除、重命名 `SpawnRequest` 字段；需要新字段写进自己 `README.md` 的待裁决，由主 AI 裁决后 3 号统一加。
3. **不得**写 `combat.*` flag 或 SaveDelta；击杀只发 I-2 信号。
4. 字段类型以此表为准；`patrol_route` 是**非类型化 `Array`（元素 Vector3）**，不是 `Array[Vector3]`（保证 `.tres` 手写零歧义）。
5. 数组字段为空时按默认值处理，不抛异常。

> 2 号任务书 §3 要求 `数据表schema.md` 也列出 `SpawnRequest` 字段；契约 I-3 与 2 号派单均注明「最终字段以 3 号定义为准」。请主 AI 汇总时按本表逐字段核对，差异见 `README.md` 待裁决 A5。
