## 1. 教学区与战斗区的空间分离

> 沿用 `WAVE-TRIAL-SPATIAL.md` §1：三波共用**同一战斗区**、不切场景、不加载打断循环。本轮新增「教学区」是**战斗区之前置的逻辑引导带**，与战斗区**逻辑分离、视觉连续**（同一庭院画面，不切场景 / 不弹全屏教学面板打断空间感）。

| # | 空间要素 | 规格（Level Designer 口径） | 约束 / rationale（`[PLACEHOLDER]` 待校准） |
|---|---|---|---|
| B-Z1 | **教学区（引导带）** | 战斗区视野内的前置引导带：开局玩家落位、金色教学 HUD 可见、玩家可自由走动试按键；**无敌人生成、无伤害判定、无 `time_limit_sec` 倒计时** | 尺度 / 位置 `[PLACEHOLDER]`；必须是「能安全地试错」的区域，过窄退无可退、过宽丢失战场纵深感 |
| B-Z2 | **战斗区** | 三波共用的连续闭合平面（沿用 SPATIAL S1~S7：生成点 S3 / 预告位 S4 / 退避带 S5 / HUD 安全区 S6 / 波间结算位 S7） | 尺度 / 退避带宽度 `[PLACEHOLDER]`；`COMPLETED` 后才激活，教学期间保持 `IDLE` |
| B-Z3 | **教学 HUD 安全区** | 金色引导提示一行（步骤文案 / 进度 1-3 / 本步奖励点数）的屏幕占位区 | 位置 `[PLACEHOLDER]`，须落在既有五套 HUD 之外的安全区（§2.1）；不遮挡退避带 / 敌人预告位 / 教学区玩家落位 |

**分离机制三条（Level Designer 底线）**：

1. **状态分离**：教学期间三波状态机保持 `IDLE`（Rank-1 `tutorial_director.gd` 与 `wave_trial_director.gd` 编排），不起倒计时、不推进波次、不生成伤害判定；`COMPLETED` 才把控制权交给第 1 波 `TELEGRAPH`。
2. **威胁分离**：教学区（B-Z1）内**不出现有效伤害体**；第 1 波敌人只在预告位 S4「可见但不激活」（§2.2），玩家从教学位到退避带 S5 全程无受击风险。
3. **时序分离**：教学区 → 战斗区是**状态切换而非场景切换**，不加载、不黑屏、不弹全屏面板；`COMPLETED` 后沿用 SPATIAL §2 的入场读秒 / 可见预告，把「学会操作」与「开始被计时」平滑接上（GDD §10.7）。

**空间分层原则（沿用 SPATIAL §1，教学不破例）**：预告位 S4 在视野内、退避位 S5 在威胁范围外、HUD 安全区 S6 / B-Z3 在屏幕边缘、生成点 S3 与退避带 S5 分离，四者**互不重叠**；教学区 B-Z1 落在战斗区可读视野内、但不与任何生成点 / 退避带 / HUD 占位重叠。任何时刻**不带即死死角、不靠隐藏墙提示**（契约 §5 的隐藏墙规则不适用于试炼区，试炼区必须可读）。

## 2. 视觉引导（HUD 位置 / 敌人预告 / 退避带）

### 2.1 教学 HUD 位置（B-Z3）

- 在既有四套 HUD 之外**新增一行金色引导提示**：步骤文案 `prompt` / 进度 1-3 / 本步奖励点数（引用 Rank-2 `tutorial_steps.tres` `[PLACEHOLDER]`），不改既有 HUD 文本。
- **必须避开既有五套占位**（坐标仅作「避开」引用，来自 Rank-1 本轮任务单，非本规格新造数值）：赐福 HUD `x<730, y<220` / 画质面板 `x>760, y<180` / 底部战斗 HUD `y≈660` / 波次 HUD `y≈232` / 兑换提示 `y≈610`。教学提示落在这五套之外的**安全区**，具体坐标 `[PLACEHOLDER]` 待 Rank-1 接线与人工试玩校准。
- 教学提示**不遮挡**退避带 S5、敌人预告位 S4 与教学区玩家落位；与 SPATIAL §3.2「HUD 与退避空间解耦」一致。
- 赐福点亮态（标题暗灰 → 亮金）由**读三段式 flag**（`grace.tutorial.completed` / 试炼完成）驱动，复用既有 `hud.gd` 第 8 节 `apply_lit_state` 入口，**不硬编码条件、不新增 HUD 层**（Rank-1 口径，本规格只登记）。

### 2.2 敌人预告（教学期 vs 战斗期）

| 阶段 | 预告位 S4 状态 | 伤害判定 | 口径 |
|---|---|---|---|
| 教学期（`NOT_STARTED`~`STEP_*`） | 第 1 波敌人轮廓 / 生成点**可见但不激活**，与 `enemy_id` / `move_weight` 对齐（SPATIAL §2.1） | **不生成** | 让玩家先看见「将来要打的敌人」建立预期，但不被打断 |
| `COMPLETED` → 第 1 波 `TELEGRAPH` | 预告位激活，入场读秒 `telegraph_sec [PLACEHOLDER]`、完整起手预告 | 读秒归零后才进 `WAVE_ACTIVE` | 沿用 `WAVE-TRIAL-SPATIAL.md` §2 逐波预告差异，**不另起一套预告规则** |

- **底线（沿用 SPATIAL §2.2「三波共同底线」）**：任何阶段都**不得取消起手预告**；高频招式（`move_weight` 高）必须先有可见前摇再生效，避免「看不见就死」。教学不靠「藏敌人」降低难度，靠「不激活伤害判定」保证安全。

### 2.3 退避带（教学期沿用战斗区 S5）

- 教学区 B-Z1 **沿用战斗区 S5 连续退避带**，不因教学收窄 / 关闭 / 上锁；玩家从教学落位能靠翻滚 / 走位到退避带再回场，路径连续、无死角。
- 教学期生成点 S3 与退避带 S5 **分离**、预告位 S4 在视野内、HUD 安全区 S6 / B-Z3 在屏幕边缘，四者互不重叠（§1 空间分层原则）。

## 3. 三步节奏（示范 → 操作 → 反馈）

> 三步 = `J` 轻攻击 / `Space` 翻滚 / `E` 赐福交互（既有 input action `light_attack` / `roll` / `interact`），逐项引用 Rank-2 `tutorial_steps.tres` 的 `step_id` / `prompt` / `expected_action` / `reward_points` / `timeout_sec` `[PLACEHOLDER]`；**步数 / 文案 / 奖励 / 超时具体值本规格一律不写、不猜**。

### 3.1 每步三段时序（三步结构一致）

| 段 | 呈现（视觉引导） | 玩家可做 | 不可做 / 门控 | 推进条件 | 时长引用 |
|---|---|---|---|---|---|
| **示范** | B-Z3 金色提示显示本步 `prompt` + 按键提示 + 目标高亮；预告位可见不激活 | 观察、在 B-Z1 内自由走动定位退避带 | 无伤害判定、无倒计时、不推进三波 | 自动进入「操作」段 | `timeout_sec` `[PLACEHOLDER]` 起算 |
| **操作** | 保持当前示范，不重复弹窗 | 只按本步 `expected_action` | **错误按键 / 非本步 action 不推进、不发奖、不写 flag、不惩罚**（GDD T-E1） | 按对触发 `tutorial_step_completed(step_id, reward)` | 同上 |
| **反馈** | 确认回执 + `reward_points` 入账（HUD 点数跳动）+ 进度 +1 + 下一步示范自动亮起 | 观察 | **不重复发奖**（GDD T-E2 幂等门控） | 自动进入下一步示范 | 由 Rank-1 状态机编排，本规格不定义时序数值 |

### 3.2 三步全完成

- 第 3 步反馈后：金色提示**收束**（不残留遮挡战斗区）、赐福标题由暗灰转亮金（读 flag）、`COMPLETED` → 自动进第 1 波 `TELEGRAPH`（§1 时序分离）。
- **教学期间三波始终 `IDLE`**；只有 `COMPLETED` 才解除「不推进三波」约束（GDD §10.7 衔接规则）。

### 3.3 节奏三条硬要求

1. **一次只教一个输入**：每步 `expected_action` 唯一，不叠加多键组合、不新增输入（GDD §10.3）。
2. **反馈即时且可见**：操作正确当帧给「确认 + 点数 + 进度」三件套，不靠文字日志、不延迟到结算。
3. **不切场景、不加载打断**：三步与第 1 波共用同一庭院画面，靠状态机与 HUD 文案切换节奏，靠空间（预告位 / 退避带 / 引导带）而非弹窗做引导。

> 三步节奏与 GDD §10.7「引导（新增最前置一层）→ 短期 30 秒 → 中期三波 → 长期最高波次 → 成长」梯度衔接：**引导层无 `time_limit_sec` 压迫**，学会后才进入被计时的短期目标；§5 难度曲线与 §9 成长循环均不回退。

## 4. 失败回退与不惩罚原则

### 4.1 四条不惩罚（GDD §10.6 T-F1 落地为空间 / 节奏规格）

| 场景 | 不惩罚口径 | 空间 / 节奏落点 |
|---|---|---|
| 错误按键 | 不推进、不发奖、不写 flag、**不死亡 / 不扣血 / 不扣点** | 保持当前「示范 / 操作」段，B-Z3 提示不变；退避带仍可自由进出 |
| 单步 `timeout_sec` 超时 | 不死亡、不扣点、不写脏 flag | 回退到**当前步**重新示范，不回到 `NOT_STARTED`、不清空已入账点数 |
| 中途退出 / 进程被杀 | 已 `commit(reason)` 的步数与点数不丢（磁盘为唯一权威） | 无空间表现；重启读回按 GDD T-E8 逐项一致 |
| `T` 强制重开 | 运行时状态机复位重走三步；**持久化 `step_index` / `completed` 不回退**、不重复发已入账点数 | 教学 HUD 进度以运行时状态机为准；点亮态保持已点亮 |

### 4.2 失败回退（层级）

- **回退粒度 = 当前步**，不是整段教学、更不是回退存档：错一步只重来那一步的「示范→操作→反馈」，已完成步的 `step_index` 与已入账 `points` 保持。
- **运行时回退 vs 持久化单调解耦**：运行时状态机可复位（T 重开 / 超时重来），但持久化 flag 按 GDD §10.8 登记为 `step_index` 单调递增、`completed` 单向，**不回写更小值**（与 §4.4「quest_stages 取较大值」同机制）；二者差异列为口径登记、不擅自改正则。
- **系统降级**：导演层 / 教学数据表 / WorldState 未就绪时安全停在 `NOT_STARTED`（B-Z1 内、无敌人、无倒计时）、**不自动进波**、不写 flag、不谎报通过（GDD T-E4 / T-F4）。

### 4.3 不惩罚 rationale（写清、不拍脑袋）

1. 开局是**学习窗口不是考核窗口**：死亡 / 扣点 / 倒计时失败会把「学操作」变成「受惩罚」，与 GDD §10.2「被牵着走的第一分钟」核心情绪相悖，直接放大入口流失。
2. **空间上给得起**：B-Z1 无伤害判定、退避带连续，玩家试错不会「进得去出不来」；不惩罚不需要靠数值放水实现。
3. **持久化单调保证复习不抹掉成就**：重开 / 超时不回退 `step_index` / `completed`，老玩家的「我学会了」与已入账点数不可撤销（GDD §10.7 留存钩子 1 / 3）。

### 4.4 失败回退规格判定项（供人工试玩核对，非脚本）

| # | 判定项 | 期望 |
|---|---|---|
| TB-B1 | 错误按键后是否仍停在当前步、无死亡 / 扣点 | 是 |
| TB-B2 | 单步超时是否只重来当前步、不清空已入账点数 | 是 |
| TB-B3 | T 重开后点亮态 / 已完成标记是否保持 | 是 |
| TB-B4 | 依赖缺失时是否安全停 `NOT_STARTED`、不自动进波 | 是 |
