# 接口契约 v1.0（4 号工位 · 对外 / 对内）

> 结论先行：4 号**不提供运行时信号或方法**，对外只提供**资源与数据契约**（`import.json` / `delivery_manifest.json` / `prompt_skeleton.json` 的字段）。唯一硬接口是 **I-5（4 → 1）**，汇报接口是 **I-6（4 → 主 AI）**；I-4 只是被消费的命名约束，4 号不实现也不修改。
> 契约第 3 节编号 I-1~I-6 已锁定，任何模块不得私改；本文件只做对齐说明，不新增、不改编号。

## 2. I-5：4 号 → 1 号（本工位唯一硬接口）

### 2.1 交付物（三件套，缺一不可）

| # | 交付物 | 路径 / 格式 | 1 号消费方式 |
|---|---|---|---|
| 1 | spritesheet | `res://assets/generated/<品类>/<name>_vN.png`，RGBA PNG32，横向等尺寸帧条 | 按 `import.json` 切帧，注册进 `SpriteFrames` / `Hybrid2D3DAnimatedSprite` |
| 2 | `import.json` | 与 PNG 同级同名 `<name>_vN.import.json`，合法 JSON | 读 `frame_width/height/columns/rows/anchor/actions/pose_names` 完成注册；读 `expected_import_settings` 核对工程设置 |
| 3 | `delivery_manifest.json` | 每批次 1 份，位于 `res://assets/generated/` | 按 `items[]` 批量导入；`layer_type=decor` 者按 `aligned_with` 叠加 |

完整字段定义、合法 JSON 示例、命名规范、逐像素对齐约束、退回条件见 `资产交付契约.md`。

### 2.2 4 号对外提供的「资源字段」（等价于本模块的 API）

> 4 号不产出 `.gd`，因此没有运行时信号 / 方法；下表即 4 号对外的全部可编程接口。

| 资源 | 关键字段 | 类型 | 消费方 |
|---|---|---|---|
| `import.json` | `frame_width` / `frame_height` / `columns` / `rows` / `frame_count` | int | 1 号（切帧） |
| `import.json` | `anchor` `{x,y}` | object | 1 号（脚贴地锚定） |
| `import.json` | `actions[]` `{name, start_frame, end_frame, fps, loop}` | array | 1 号（SpriteFrames 动画注册） |
| `import.json` | `pose_names[]` | array[string] | 1 号 → I-4 `set_pose()` 注册 |
| `import.json` | `palette[]` | array[string] | 1 号核对 / 4 号风格复核 |
| `import.json` | `layer_type` / `aligned_with` | string / string\|null | 1 号（装饰层叠加，禁止运行时偏移校准） |
| `import.json` | `seed` / `downsample` / `pipeline_tier` / `fallback_route` | 混合 | 复核与可追溯，不参与运行时 |
| `import.json` | `expected_import_settings` | object | 1 号落地后核对 |
| `delivery_manifest.json` | `items[]` / `batch_id` / `milestone` / `interface` | 混合 | 1 号批量导入依据 |
| `prompt_skeleton.json` | `positive` / `negative` / `style` / `lighting` / `palette` / `seed_lock` | 混合 | 4 号生产端 / 主 AI 复核（**1 号不消费**） |

### 2.3 对 I-4 的对齐（`pose_names`）

- I-4 规定 1 号封装 `set_pose(pose_name, frame_index)`，2 号只调此方法。
- 4 号的 `import.json.pose_names` 必须**逐字等于** 1 号在该节点中注册的 `pose_name` 集合的子集，且与 `actions[].name` 一一对应。
- 当前建议集合：`idle` / `walk` / `jump` / `roll` / `attack` / `hit` / `death`（与 `prompt_skeleton.json` 的 `seed_lock.action_offset` 一致）。
- **待确认**：最终枚举由 1 号 / 2 号定；4 号不私改，写进 `README.md`「待主 AI 裁决」，冻结后再统一重出受影响的 `import.json`。

### 2.4 4 号对 1 号的依赖（反向清单）

| # | 需要 1 号提供 | 用途 | 缺失时 4 号的处理 |
|---|---|---|---|
| 1 | `pose_name` 最终枚举（I-4） | 冻结 `pose_names` / `actions` | 用建议集合出 M0 底稿，标注「待冻结」，不擅自扩名 |
| 2 | `Hybrid2D3DSprite` 的**像素→米缩放比**与自定义 AABB 口径 | 确认 32px 与 anchor (16,31) 在 3D 地面上正确 | 视觉规范里按 32px / 底部中心写死，标注为假设 |
| 3 | 项目级导入设置的**实际落地值** | 与 `expected_import_settings` 核对 | 差异写进 `README.md` 待裁决，不改 1 号文件 |
| 4 | 图集分组策略（品类 / 动作维度） | manifest 备注里对齐 | 按「同品类+同动作优先、`bg_layers` 单独分组」给建议 |
| 5 | 低分辨率渲染缓冲尺寸与整数倍 | 确认 640×360 / 3x 基准 | 视觉规范写 640×360 整数倍，标注为假设 |
| 6 | 装饰层叠加顺序确认（`base → cloth → hair → eyes`） | 避免运行时校准 | 按资产契约 §4 执行，冲突上报 |

> 4 号**不依赖** 2 号 / 3 号的运行时数据（战斗数值、flag、存档），也不订阅任何信号。
