# 资产交付契约 v1.0（I-5 · 4 号 → 1 号）

> 结论先行：4 号交付的最小单元是「**1 张 RGBA PNG + 1 个同级 `import.json`**」，批次用 1 个 `delivery_manifest.json` 汇总。1 号**只按清单切帧注册与叠加装饰层**，不猜参数、不做运行时偏移校准。所有 JSON 合法可解析，`res://` 路径一律 snake_case。
> 对齐契约第 3 节 I-5（4 → 1）、I-4（1 → 2 的 `set_pose(pose_name, frame_index)`）。接口编号不得私改。

---

## 1. 目录规范

```text
res://assets/generated/
├── _style_anchor/
│   └── style_anchor.png              ← 全项目唯一风格锚点图，任何批次不得替换
├── _pose/
│   └── <action>_<frame>.json         ← 共享 OpenPose 骨架库，跨角色复用
├── chars/                            ← 角色 / 敌人 / Boss 基础帧条
│   └── _pose/                        ← （可选）chars 专用骨架副本
├── decor_layers/                     ← hair / eyes / cloth 独立 RGBA 装饰层
├── fx/                               ← 光尘 / 打击 / 赐福 / 体积光贴图
├── bg_layers/                        ← 7 层视差背景（bg_0_sky ~ fg_0_occl）
├── props/                            ← 道具 / 环境瓦片 / 碎石
├── ui/                               ← 九宫格 / 角饰 / 图标 / 分隔线
└── delivery_manifest.json            ← 当前批次总清单（每批次一份，批次 id 唯一）
```

| 规则 | 说明 |
|---|---|
| 品类固定 6 个 | `chars` / `decor_layers` / `fx` / `bg_layers` / `props` / `ui`，不新增品类；需新增报主 AI 裁决 |
| 三件套 | 每个 spritesheet = 1 个 `RGBA PNG` + 1 个**同级同名** `import.json`（如 `a.png` ↔ `a.import.json`… 见 §3 命名）；批次 1 个 `delivery_manifest.json` |
| 路径 | 一律 `res://assets/generated/<品类>/<文件>`，snake_case，禁止中文/空格/大写 |
| 不产出 | 4 号不产出 `.gd` / `.tscn` / `.tres`（属 1 号）；不写 Godot 工程根目录之外任何文件 |
| 版本 | 文件名带 `_v1` 版本号；同资产迭代升 `_v2`，不覆盖旧版，便于回滚与复核 |

## 2. `import.json` 完整字段定义

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `schema_version` | string | ✅ | 契约版本，当前 `"1.0"` |
| `asset_id` | string | ✅ | `<品类短名>_<序号>_<slug>_<版本>`，全局唯一 |
| `res_path` | string | ✅ | `res://` 开头的 PNG 路径 |
| `sprite_sheet` | string | ✅ | PNG 文件名（含扩展名） |
| `frame_width` | int | ✅ | 单帧宽，角色固定 `32` |
| `frame_height` | int | ✅ | 单帧高，角色固定 `32` |
| `columns` | int | ✅ | 帧条列数 |
| `rows` | int | ✅ | 帧条行数（单动作帧条为 `1`） |
| `frame_count` | int | ✅ | 有效帧数，≤ `columns * rows` |
| `anchor` | object | ✅ | `{"x": 16, "y": 31}`，底部中心脚贴地；全帧共用 |
| `actions` | array | ✅ | 每项 `{name, start_frame, end_frame, fps, loop}`；`start/end_frame` 为**全局线性帧索引**（`row * columns + col`） |
| `pose_names` | array[string] | ✅ | 与 `actions[].name` 一致，供 1 号注册进 `set_pose(pose_name, frame_index)`（I-4）；**不得出现清单外的名字** |
| `palette` | array[string] | ✅ | 实际使用色号 hex，必须全在 `HD-2D视觉规范.md` §2.2 的 32 色共享板内，且 ≤ 16 色/角色 |
| `layer_type` | string | ✅ | `base` / `decor` / `bg` / `fx` / `ui` |
| `aligned_with` | string\|null | 装饰层必填 | 装饰层填对应 base 的 `res_path`；非装饰层填 `null` |
| `seed` | int | ✅ | 由 `prompt_skeleton.json` 的 `seed_lock.derivation` 派生；装饰层必须与 base **完全相同** |
| `downsample` | object | ✅ | `filter` / `colors` / `dither` / `target_size`，装饰层须与 base 一致 |
| `expected_import_settings` | object | ✅ | 4 号声明**期望值**，由 1 号在工程侧落地并核对（§5） |
| `pipeline_tier` | string | ✅ | `A`/`B`/`C`/`D`，见 `美术管线.md` §7 |
| `fallback_route` | string | ✅ | `none` / `single_frame_hand_interpolation` / `procedural_draw_placeholder` |
| `prompt_skeleton` | string | ✅ | 固定骨架 id，当前 `hd2d_pixel_skeleton_v1` |
| `human_refine` | string | ✅ | `required` / `done` / `not_required`；主角 / Boss / 关键场景必须 `done` 才允许交付 |
| `generated_at` | string | ✅ | `YYYY-MM-DD` |
| `version` | string | ✅ | 与文件名 `_vN` 一致 |

## 3. 命名规范

| 对象 | 规则 | 示例 |
|---|---|---|
| PNG / import.json | `snake_case`，形如 `<subject>_<action>_v1.png` / `<subject>_<action>_v1.import.json` | `player_tarnished_walk_v1.png` |
| 装饰层 | `<subject>_<layer>_<action>_v1.png`，`<layer>` ∈ `hair`/`eyes`/`cloth` | `player_tarnished_eyes_idle_v1.png` |
| 背景层 | `bg_<index>_<slug>_v1.png`，index 对应视觉规范 §3 层 ID | `bg_1_far_silhouette_v1.png` |
| `asset_id` | `<品类短名>_<两位序号>_<slug>_<版本>` | `char_01_player_tarnished_walk_v1` |
| 批次 id | `batch_<YYYYMMDD>_<milestone>_<品类>` | `batch_20261108_m0_chars` |
| 路径 | 一律 `res://assets/generated/<品类>/...`，不用绝对路径、不用 `user://` | — |
| 禁止 | 中文、空格、大写字母、连字符、版本号缺失、跨品类混放 | — |

**帧条形态**：
- 形态 A（M0 推荐）：单动作横向帧条，`rows = 1`，`columns = 帧数`，`actions` 仅 1 项。
- 形态 B（M2+ 可选合表）：多动作按行排列，`rows = 动作数`，`start_frame`/`end_frame` 用全局线性索引 `row * columns + col`；`pose_names` 列出全部动作名。1 号按 `actions` 切帧注册，无需额外约定。

## 4. 装饰层 RGBA 逐像素对齐规范（硬约束）

> 结论：对齐是**生产阶段的责任**，不是运行时的工作。1 号只做叠加，禁止任何运行时偏移校准。

| # | 约束 | 校验方式 |
|---|---|---|
| 1 | 尺寸一致 | `frame_width` / `frame_height` / `columns` / `rows` / `frame_count` 与 base 完全相同 |
| 2 | 帧序一致 | 第 N 帧装饰对应第 N 帧 base，`actions` 的 `start/end_frame`、`fps`、`loop` 完全相同 |
| 3 | 坐标系一致 | 同一 `anchor`（`{x:16, y:31}`），同一原点、同一帧网格，禁止逐帧偏移 |
| 4 | seed 一致 | 装饰层 `seed` 必须**等于** base 的 `seed`（`美术管线.md` W4 节点 `11`） |
| 5 | 降采样参数一致 | `downsample.filter` / `colors` / `dither` / `target_size` 完全相同（Point / 16 / None / 32×32） |
| 6 | 非装饰区全透明 | mask 外 alpha 必须为 `0`；`RGBAAlphaMask` 强制；不得有半透明脏边 |
| 7 | 色板一致 | 装饰层取色限共享 32 色板，与 base 不冲突 |
| 8 | `aligned_with` 必填 | 指向 base 的 `res_path`；缺字段直接判不合格退回 |
| 9 | **禁止运行时校准** | 1 号不得为装饰层加 offset / pivot 补偿；若叠加出现 1px 偏移，判装饰层**重做**，不在引擎侧打补丁 |

**叠加顺序**（1 号按此注册，从下到上）：`base` → `cloth` → `hair` → `eyes`。同帧同坐标直接相加，不缩放、不旋转、不平移。

## 5. Godot 导入设置（4 号声明期望值，1 号落地）

| 设置 | 期望值 | 责任 |
|---|---|---|
| `compress_mode` | `lossless`（无损） | 1 号落地 |
| `mipmaps` | `false`（关闭） | 1 号落地 |
| `texture_filter` | `Nearest` | 1 号落地 |
| 项目级 `default_texture_filter` | `0`（Nearest） | **1 号落地**（契约 §5 明确），4 号只在 `import.json` 的 `expected_import_settings` 声明供核对 |
| `fix_alpha_border` | `true` | 1 号落地，防透明边杂色 |
| 图集分组 | 同品类 + 同动作优先合图集；`bg_layers` 单独分组（尺寸差异大） | 1 号定，4 号在 manifest 备注 |
| 像素化后处理 | 640×360 低分辨率缓冲 + 整数倍 Nearest 放大 | 1 号落地，见视觉规范 §3 |

> 4 号**不改** Godot 工程设置、不写 `.gd`/`.tscn`；`expected_import_settings` 只是核对基准。1 号落地后若实际值与期望值不符，由 1 号反馈，4 号不改别人文件，冲突写进 `README.md`「待主 AI 裁决」。

## 6. I-5 对 1 号的交付清单格式

每次交付，4 号向 1 号提供以下三项（缺一不可）：

| # | 交付物 | 格式 | 1 号的动作 |
|---|---|---|---|
| 1 | `res://assets/generated/<品类>/*.png` | RGBA PNG32 帧条 | 按 `import.json` 切帧，注册进 `SpriteFrames` / `Hybrid2D3DAnimatedSprite` |
| 2 | 同级 `*.import.json` | 合法 JSON，字段见 §2 | 读 `frame_width/height/columns/rows/anchor/actions/pose_names`，把 `pose_names` 注册到 I-4 的 `set_pose(pose_name, frame_index)` |
| 3 | `delivery_manifest.json` | 合法 JSON，`items[]` 逐项列出 | 按 `items[]` 批量导入；`layer_type=decor` 的按 `aligned_with` 叠加 |

### 6.1 交付附带说明（每次必写）

```text
批次 id / 里程碑 / 品类 / 档位与降级路线 / 本批次资产数 / 哪些是 AI 底稿、哪些已人工精修 /
需 1 号核对的期望导入值 / 已知未完成项 / 风格锚点版本
```

### 6.2 1 号的验收动作（真跑，不写探针）

1. 按 `delivery_manifest.json` 导入全部 PNG，确认无导入报错。
2. 读一张 `import.json`，按 `columns/rows/frame_width/frame_height` 切帧，确认帧数与 `frame_count` 一致。
3. 把角色放到 3D 地面，确认**脚贴地**（anchor (16,31) 生效）、像素清晰无锯齿、无 z-fighting。
4. 调一次 `set_pose("walk", 2)`，确认停在 walk 第 2 帧（I-4 通路打通）。
5. 叠一个 `decor` 层，确认**无 1px 偏移**、非装饰区完全透明；如有偏移，退回 4 号重做，不在引擎侧补偿。
6. 核对 `expected_import_settings` 与工程实际值，差异写回 4 号记录。

### 6.3 退回条件（任一命中即整批次退回）

- JSON 解析失败或字段缺失；`aligned_with` 缺失（装饰层）；`pose_names` 与 `actions` 不一致。
- 帧尺寸不等宽、脚底 Y 漂移、非透明区有杂边、色数 > 16、色号不在共享板内。
- 装饰层与 base 的 seed / 降采样参数 / 尺寸 / 帧序任一不一致。
- 主角 / Boss / 关键场景 `human_refine != "done"`。
- 出现任何付费素材、外部生成服务产物，或来源 / seed / 版本号标注缺失。
