### 1.1 数值拆解 / rationale（全部 `[PLACEHOLDER]`）

- **调参唯一入口**：`godot/scripts/rpg/points_commit_orchestrator.gd` 常量段 `COST_TO_POINTS_FACTOR` / `COST_TO_POINTS_MIN` / `COST_KEY_WHITELIST`（集中一处、**只改常量不改逻辑**）；目录所有权冻结、本轮不新增数据表。Rank-2 的 `parry_rules.tres` / `boon_draft.tres` 由 Rank-2 所有、Rank-3 只读消费。校准同步清单：常量段 → `verify_v120_save_commit.gd` `FIX_*` → `verify_spent_points_production_v120.gd` `FIX_*` → 契约 §3.3 R35 段 → 本文数值表 → 三段门禁；不静默改数。
- **`COST_TO_POINTS_FACTOR = 10.0`** `[PLACEHOLDER]`：Rank-2 `boon_draft_service.apply()` 的 `cost_value` 是「下一波敌人难度乘性修正」（`hp_scale` / `telegraph_scale`，> 0 倍率）**并非赐福点数**；A59 需把它折算成点数消耗，采用线性换算 `points_cost = max(MIN, round(cost_value × FACTOR))`。取 10.0 使 `cost_value=1.5` → 15 点（与既有 `execute_bonus_points=50` / `points_bonus=50` 同量级、不盖过产出）；真实经济平衡（点数产出速率 vs 抉择代价）须人工试玩校准，headless 真跑不做手感判断。
- **`COST_TO_POINTS_MIN = 1`** `[PLACEHOLDER]`：夹取最小扣点，防止 `cost_value` 极小时 `round()` 归 0 造成「解锁了但没扣点」空转。
- **`COST_KEY_WHITELIST`**：与 Rank-2 `boon_draft_config.gd::is_cost_key_known` 白名单对齐；未来新增 `cost_key` 须同步本常量，否则按「非法值」拒绝并告警（不静默吞掉）。
- **弹反数值**（`window_sec=0.35` / `cooldown_sec=1.2` / `poise_bonus=25.0` / `points_bonus=50` / `combo_keep` / `fail_penalty`）全部归 Rank-2 `parry_rules.tres`，Rank-3 **不落盘倍率、不二次加工、不自行叠加**（A57 / A60）。

## 3. GDD 六项（game-development-pro）

| 项 | 内容 |
|---|---|
| **Purpose（目的）** | 给「精准弹反」与「赐福抉择」两条玩法补上**消费闭合**：弹反每个窗口的点数都真实入账（A58），抉择代价真正落到可支配余额（A59），让「行动 → 反馈 → 目标 → 消费成长 → 再行动」长期动机断点闭合，且不破坏 A55 点数落盘唯一权威通道。 |
| **Player experience goal（玩家体验目标）** | 玩家连续两次成功弹反能看到赐福点数**各加一次**（不再第二次「消失」）；做抉择时能看到「余额 = 点数 − 已花费」真实下降、解锁态点亮，同一抉择重复点不重复扣；重启后消费 / 弹反态不丢。 |
| **Inputs（输入）** | 生产信号 `boon_draft_applied(index, choice_id, effect_key, effect_value, cost_key, cost_value)`、`production_wave_modifier(wave_index, effect_key, effect_value, cost_key, cost_value)`、`parry_performed(window_id, bonus_points, poise_bonus)`、`points_awarded(reason, points, source)`、`execution_performed(window_id, bonus_points)`；真实输入 `Input.parse_input_event`（K / F / 数字键）经 HUD → 上述信号。 |
| **Outputs（输出）** | 磁盘 `user://saves/slot_01/delta.json` 的 `flags`：`grace.trial.spent_points`（单调累加）、`grace.boon_draft.unlocked` / `.selected` / `.cost_applied`、`combat.parry.success_count` / `.window_id`、`grace.trial.points`（A55 原样累加）、`grace.execution.performed`；`meta.last_commit_reason`；信号 `committed(reason)` / `points_committed(...)` / `hud_bound(hud)`；`get_status()` 只读观测（claimed / charge_reject_count / parry_count 等）。 |
| **Edge cases（边界）** | ① 空 `window_id` → 降级唯一 fallback 键 + 告警；② 缺失 / 非法 cost（空 key、白名单外、≤0、NaN、Inf）→ 拒绝 + 告警；③ 余额不足 → 前置门控拒绝、不落盘；④ 同一抉择重复购买 / 同一窗口重放 → 去重拒绝；⑤ 旧档缺新 key → `get_flag(key, default)` 回落基线、不升级 / 不迁移；⑥ `--script` 模式 autoload `_ready()` 未 flush → 正则 / 运行时镜像惰性初始化兜底；⑦ 无 HUD 的纯 `--headless --quit` / `--import` → 绑定降级、不订阅、不写盘、不报错；⑧ `production_wave_modifier` cost 与已入账抉择不一致 → 对账告警、不二次扣费。 |
| **Failure states（失败态）** | `commit` 原子写失败 → 运行时镜像保持旧值、不 emit、不解锁、不扣点、如实告警；`_atomic_write` `.tmp → flush → rename` 失败返回 false；`_validate_ten_fields` / 三段式正则 / 标量白名单校验失败 → 本次不落盘；点数溢出 / 负点数 / `points` 回退 → 拒绝。所有失败态均「磁盘未改、内存未改」，绝不「内存已改、磁盘未改」。 |
