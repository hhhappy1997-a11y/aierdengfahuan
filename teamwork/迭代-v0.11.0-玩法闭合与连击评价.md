## 1. 版本定位与核心循环诊断（Game Designer）

R34A / R34B 已把连击评价、赐福抉择、韧性处决**接进真实玩法**（Rank-1 6 链 + A54 唯一实例收敛、Rank-2 combo/settlement 数据表与纯逻辑），但 Rank-3 侧遗留两处断点，本版闭合：

| 断点 | 来源 | 本版补法 | 闭合后的循环 |
|---|---|---|---|
| **点数落盘口径分叉** | R34B §4.4 登记：`wave_cleared(index, points)` 第二参仍是**基础 pts**，而 combo 倍率已并入导演层落盘值；Rank-3 若按 `wave_cleared` 累加 `grace.trial.points` 会与导演层倍率后值分叉 | **裁决 A55**：`points_awarded(reason, points, source)` = 点数落盘**唯一权威通道**，Rank-3 订阅它写入 `grace.trial.points`；`wave_cleared` 只作 HUD 展示基础值、`combo_settled` 只作对账与展示 | 一次结算 → 一个入口 → 磁盘唯一权威，分叉消除、点数不通胀 |
| **R32 四 flag 登记未接线** | DONE-R32 §4 第 6 条 / DONE-R34B §7 第 1 条：抉择 / 破韧 / 处决 4 个 flag「已登记口径、运行时写入未接线」 | 在 I-1 权威写入点**登记落盘接线口径**（订阅信号 → 事件键配对去重 → `set_flag` → `commit(reason)` 原子落盘 → 先落盘后改实例）+ 新增 2 个连击评级 flag + 三进程三态只读验证 | 抉择 / 处决 / 连击的点数与 flag 落盘口径闭合，磁盘可回读 |
| **「真实可达」与「口径验证」边界不清** | 演示驱动（开窗 / 抉择卡片）曾被当作可玩交付 | **裁决 A49**：真实可达须在**不加载 `presentation.gd` 的进程里由真实输入连通**；Rank-3 headless 三态只验「落盘口径 + 磁盘一致性」，不冒充真实可达 | 验收口径可机器判定、不谎报 |

| **P1** | **「口径验证」被误读为「真实可达」**：headless 三态只验磁盘一致性，不等于新机制在真实输入下连通 | 演示驱动冒充可玩交付 | **A49** 明确：真实可达须在不加载 `presentation.gd` 的进程里由真实输入连通（Rank-1 `verify_combo_runtime_v110.gd` 口径）；Rank-3 三态脚本文件头显式声明「不冒充真实可达」 | 真实可达验收归 Rank-1 / 总指挥，Rank-3 不代判、不谎报 |

## 9. 风险、假设与回滚方案

- **并发写入**：本轮四路并发，`encounter_director.gd` / `hud.gd` / `wave_trial_director.gd` / `combo_service.gd` 归 Rank-1 / Rank-2；Rank-3 全部读写落在独立临时槽 `user://saves/verify_v110_<RUN>/`，对生产 `slot_01` 只做 `get_md5` 只读前后对照，避免共享 `delta.json` 造成回归抖动（R27/R31/R32 先例）。
- **`--script` 模式**：手动 `new()` 的 WorldState 不进场景树、`add_child` 不自动 flush `_ready()`，一律显式 `call("_ready")`；探活走 `Engine.get_main_loop() as SceneTree` 相对路径，不用 `get_tree()` / `/root/...`；资源回读 `CACHE_MODE_IGNORE`。
- **「新进程 load」等价口径（如实登记、不伪造）**：`world_state.gd::_load()` 的 `DELTA_PATH` 常量写死生产 `slot_01`，「不碰生产存档」约束下不能把测试快照写进生产槽；`_load()` 对 `schema_version=3` 且无 `delta.log` 的干净 delta 的实质动作是 `_migrate()`（恒等）→ `_replay_log([])`（恒等）→ `_apply_snapshot(state)`，故三态验证改走「自读独立槽 `delta.json` → 新建 WorldState → `_apply_snapshot`」，语义等价于 `_load()` 注入段、数据源指向独立槽。列为待总指挥裁决项（沿用 R31/R32 同型）。
- **编排夹具边界（如实登记、不伪造）**：`_sig_*` 一组函数是 Rank-3 I-1 落盘编排的**确定性自包含口径夹具**，不加载 `presentation.gd`、不连真实 HUD 信号、不改 `godot/` 业务代码；验证的是「口径 + 磁盘一致性」，**不冒充运行时已接通**（A49 / A50）。`points_awarded` 清波权威值夹具取 `160`（A 级 `1.6` 倍率后）仅作分叉消除判据，真实值以 Rank-1 发信号实现为准、Rank-3 原样采信。
- **JSON int→float**：`JSON.parse_string` 把 int 读回为 float（日志 `performed=1.0` / `points=210.0` / `schema_version=3.0`），由 `_val_eq` / `int()` 容忍，不影响三段式正则 / 类型 / 余额判定，如实登记不隐藏。
- **`[PLACEHOLDER]` 数值**：夹具 `100 / 160 / 50 / 30 / 14 / "A" / 1.6 / "boon_frost_edge"` 只用于确定性三态回读、非设计数值；试玩校准后需同步迭代文档 / 验证脚本 `FIX_*` 常量 / DONE / 数据表，不静默改数。
- **回滚**：① 删除 `verify_v110_save_commit.gd`、迭代文档、`DONE-R34.md`、回执；② 契约 §3.3 只撤 R34 说明段、存档规范 §3.3 只撤 2 行 + R34 注记、README 只撤 v0.11.0 追加段（历史行逐字保留）；③ 重跑 `--import` + `--check-only --script` + `--quit` 确认 `SCRIPT ERROR=0`、既有 31 PASS 存档/HUD 回归不回退、`courtyard.tscn node_count=41` 不变。**不触碰任何 `godot/` 业务代码与其它 Rank 产出**。
