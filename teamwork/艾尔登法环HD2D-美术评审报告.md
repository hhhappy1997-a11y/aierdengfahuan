# 艾尔登法环HD2D-美术评审报告

> 版本 v1 ｜ 2026-11-09 ｜ 设计分辨率 1280×720（像素层逻辑画布 128×128）｜ 目标引擎 Godot 4.7.2 ｜ 档位 desktop / mobile
> 评审对象：R23 本机 ComfyUI 素材 `godot/assets/generated/r23/`（玩家 8 帧、Boss 3 招、装饰层、地面 tile）与实机录屏 `capture/r23_final.mp4` 首帧
> 评审依据：项目此前**未确立过风格锚点**，本报告先给出重做判据；锚点草案见同目录 `艾尔登法环HD2D-美术风格提案.md`

## 评审结论

**总体：重做。** 不是调色或修边能解决的「小改」，是**生成管线 + 风格锚点**层面的结构性错误。

用户原话「像素化不是马赛克」成立：像素画是「每个像素被有意识地放置」，现有素材是「连续色调高分辨率图被降采样后的色块」。两者放大后都是方块，但前者方块有轮廓与明度意图，后者是原图局部平均后的杂色。

硬证据：`capture/r23_thumbnail_test.png` 的 10% / 25% 缩略图测试 —— 角色 10% 完全认不出持剑盾骑士，地面 10% 退化为无结构灰棕杂色；按 `references/review.md` 判据「10% 认不出主体 → 重做」。

## 六维打分（1–5）

| 维度 | R23 现状 | 分 | 5 分标准对照 |
|---|---|---:|---|
| 剪影可读性 | 10% 缩略图骑士轮廓消失，剑/盾与躯干明度接近，四肢糊在一起 | **2** | 涂黑后仍能认出，缩到 10% 依然清晰 |
| 明度层级 | 亮度实测跨 0–254 全阶，主体与地面同处中间调，灰度下不分 | **2** | 主体/次体/背景三段分明，转灰度仍分得清 |
| 构图与负空间 | 角色细节满铺无留白；地面 128×128 塞几十块碎砖 + 磨损噪点，无视觉重心 | **2** | 视觉重心明确，留白合理 |
| 风格一致性 | 角色是像素、地面是高细节写实纹理、背景是平滑景深、UI 是金线矢量 —— 四套语言 | **2** | 线宽、比例、色彩、质感同族 |

| **合计** | — | **13/30** | **重做** |

## 问题清单（问题 → 为什么是问题 → 具体改法）

## 缩略图测试（必做，已跑）

- **10%**：R23 角色认不出持剑盾骑士 → 触发重做判据；R23 地面成无结构灰棕杂色块。
- **25%**：R23 角色内部细节糊、武器与躯干同明度；基准图 v1 的红缨 / 头盔 / 肩甲 / 盾 / 剑仍清晰可辨。
- 证据文件：`capture/r23_thumbnail_test.png`、`capture/r23_baseline_thumbnail.png`、`godot/assets/generated/r23_baseline/player_idle_v1.png`（透明底）与 `player_idle_v1_solid.png`（纯色底 #FF00FF 复核版）。

## 需精修项（与「可直接使用」分开）

- 基准图 v1 是**程序化规格示意**，头盔面甲、手部、靴子、剑柄仍需人工逐像素精修；不承诺可直接商用。
- R23 全部 13 张素材**不可直接入图集**，需按风格提案 v1 重做；旧版保留供回溯（版本号 `_v1` → `_v2`，不覆盖）。
- 任何 AI/程序生成图都需人工精修与合规确认后才能作为最终素材。

## 建议推进顺序

1. **先定调**：确认风格锚点 v1 与 6 色色彩板（未确认前不批量放量）。
2. **改管线**：冻结单帧 ≤16 色索引 + 128px 原生逻辑网格，禁止降采样。
3. **只做 2 张**：`player_idle_v2` + `ground_tile_v2`，跑 10% / 25% 缩略图测试与色数校验。
4. **用户确认后**再批量放量：玩家 8 帧 → Boss 3 招 → 装饰层 → UI 图标。
5. **最后**才接入 Godot、跑三段门禁、重录 15 秒实机画面并回看。
