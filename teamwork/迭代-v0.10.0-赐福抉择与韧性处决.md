## 1. 核心循环诊断（Game Designer）

v0.9.0 已闭合「试炼词条 + 满愿图鉴 + 存档三态回读」，但一局内的**决策层**仍薄：波间只累加既有词条，玩家在「打完一波 → 下一波」之间缺一次主动取舍；Boss 战则缺「破韧 → 处决」的爆发窗口，命中反馈只做数字增长、无可读的窗口态。本版补两个相邻断点：

| 断点 | 本版补法 | 闭合后的循环 |
|---|---|---|
| 行动→反馈之间缺「取舍」 | **赐福抉择**：波间/赐福交互给出候选恩惠，选定后代价落账，写 `grace.boon_draft.selected` / `.cost_applied` | 行动 → **抉择** → 反馈 → 目标 → 消费成长 → 再行动 |
| 命中反馈缺「爆发窗口」 | **韧性处决**：累计命中破韧后开窗，窗内可处决，写 `combat.boss_01.stagger_window` / `grace.execution.performed` | 命中 → **破韧开窗** → 处决 → 累计成就 → 再挑战 |
| 新机制无存档口径 | **四个三段式 flag 登记**（契约 §3.3 R32 段 + 存档与flag规范 §3.3 全局表）+ 三进程三态只读回读验证 | 磁盘为唯一权威，重启读回一致 |

> 三类新数值（试炼词条 / 赐福抉择 / 韧性处决）**全部 `[PLACEHOLDER]` 待人工试玩校准**（裁决 A45）；Rank-3 只登记口径与写只读验证脚本，**不写 `godot/` 业务代码、不代验其它 Rank 运行时接线**。

## 3. 漏洞识别 P0 / P1 / P2（主动识别，含修补与残留）

| 级别 | 漏洞 | 表现 | 本版处置 | 残留 / 归属 |
|---|---|---|---|---|
| **P0** | **循环断裂**：抉择/处决只有运行时态、无持久化口径，重启后「选了什么 / 处决几次」丢失 | 玩家决策与成就不跨局 | 四个三段式 flag 登记 + `commit(reason)` 强制落盘点 + 「先落盘再改运行时实例」五步 + 三进程三态回读验证（磁盘唯一权威） | 运行时接线归 Rank-1/Rank-2 并发，Rank-3 不代验；口径已闭合 |
| **P1** | **数值通胀**：抉择代价 / 处决奖励若与既有 `points` 叠加无上限，会冲垮 R27 余额非负约束 | `points − spent_points < 0`、奖励刷屏 | 抉择代价走既有 `spent_points` 出口语义、`performed` 只 +1 不回写 `points`、余额非负硬约束入三态断言（C01/C02/C03）；**不写 `removals`、不回退 `points`** | 具体 `[PLACEHOLDER]` 数值待人工试玩校准（A45），Rank-3 不代做 |
| **P1** | **前 3 分钟无引导**：新抉择/处决机制若开局直接弹出，老玩家不知按键、新玩家无「为什么」 | 开局 180 秒无目标、面板突兀 | 承接 R28 三步教学 `grace.tutorial.completed` 门控：教学完成前不推进抉择/不弹处决提示；抉择/处决提示挂既有教学 HUD 之后 | 教学与抉择的衔接时序属 Rank-1 运行时接线，Rank-3 不代验；如实测仍无引导交用户试玩回报 |
| **P1** | **面板遮挡**：抉择面板若盖住角色 / 四套 HUD | 界面不可读、判定区被盖 | 沿用 R29B/R30 面板安全区口径（独立 `CanvasLayer`、默认隐藏、避开赐福 HUD `x<730,y<220` / 画质 / 波次 / 教学 / 兑换 / 底部 HUD 与玩家/Boss 包围盒）；布局回归 `verify_hud_layout_v100.gd` 归 Rank-1 | 本版未真跑布局脚本（其它 Rank 产出、不代验），如实登记 |
| **P2** | **处决窗口不可读**：窗口只靠颜色 / 无形状差异，或时长过短无法反应 | 玩家错过窗口、状态不能只靠颜色区分（违反锚点 v2 J6） | 口径要求窗口态带形状/图标差异（J6）、`stagger_window` 供 HUD 增量刷新；`[PLACEHOLDER]` 窗口时长待试玩校准 | 画面可读性属 Rank-4 录屏目视 + 用户试玩（A42），headless 无帧缓冲、Rank-3 不代判 |

> 补充边界（公共契约）：重复点击 / 超限数值 / 节点未就绪三类异常——抉择防重复扣费门控、`performed` 单调只增不越界、`--script` 模式 WorldState 用 `Engine.get_main_loop()` 相对探活 + `CACHE_MODE_IGNORE`，均已在只读验证脚本中构造并回归。

## 4. GDD 六项（game-development-pro）

| 项 | 内容 |
|---|---|
| **purpose** | 给 v0.9.0 的一局内循环补「主动取舍（赐福抉择）」与「爆发目标（韧性处决）」两层，并把二者状态收敛进既有 `SaveDelta` 十字段、`schema_version=3` 冻结结构，闭合决策/成就的跨局持久化断点。 |
| **player experience goal** | 玩家在波间感到「我在选」而非「自动继续」；在 Boss 战感到「打满 N 次命中能开窗处决」而非纯磨血；选定恩惠与处决次数在退出重开后仍在。 |
| **inputs** | 赐福交互 / 抉择面板选择事件（Rank-1）；`player_hit_landed` 命中信号（A39/A44，Rank-1 `encounter_director.gd` 唯一写入方，只新增信号 + 一处 emit）；Rank-2 `boon_draft_service` / `stagger_service` 纯逻辑判定结果；既有教学 `grace.tutorial.completed` 门控。 |
| **outputs** | 四个三段式 flag 经 I-1 `set_flag` 写入 `flags` 字典；`commit(reason)` 原子落盘；`flag_changed` 增量刷新抉择 HUD / 处决窗口提示 / 打击反馈层；`delta_committed` 供回放。 |
| **edge cases** | 旧存档缺 4 个 key → `get_flag(key, default)` 回落 `"" / false / false / 0`、不升级不迁移；`_load()` 后 `selected` 非空 / `cost_applied` / `stagger_window` 为 `true` 且无活跃实例 → 判异常中断置基线；重复抉择不二次扣费；重复处决只 +1；JSON int→float round-trip 由比较器容忍；独立临时槽与生产 `slot_01` 物理隔离。 |
| **failure states** | `commit(reason)` 失败 → 不执行运行时实例更新、保持旧值、如实告警，绝不「内存已改、磁盘未改」；余额不足 / 重复购买由 Rank-2 门控拒绝（不写任何 flag）；`schema_version > 3` 拒绝加载；命中信号未就绪时处决窗口不打开（依赖降级，不崩）。 |

## 6. 节点与信号链架构（只读登记，运行时接线归各自 Rank）

```
[Rank-1 唯一写入] encounter_director.gd  ── 新增 signal player_hit_landed + 一处 emit（A39/A44，其余 Rank 只读）
        │
        ▼
[Rank-2 纯逻辑/数据表] stagger_service.gd / stagger_rules.tres ──破韧判定──▶ 处决窗口编排
[Rank-2 纯逻辑/数据表] boon_draft_service.gd / boon_draft.tres  ──抉择判定──▶ 抉择编排
        │（判定通过后触发，不直接读写存档文件，I-1）
        ▼
[Rank-3 I-1 权威] WorldState.set_flag(key, value)
        │  ├─ grace.boon_draft.selected      (String / 局内翻转)
        │  ├─ grace.boon_draft.cost_applied  (bool   / 局内翻转)
        │  ├─ combat.boss_01.stagger_window  (bool   / 局内翻转)
        │  └─ grace.execution.performed      (int    / 单调只增)
        │  只作 flags 字典新 key；十字段冻结 / schema_version=3 / removals 空
        ▼
    commit(reason) 原子写 .tmp → flush → rename → delta.json   ★ 先落盘
        │  reason: boon_draft_selected / boon_draft_cost_applied / stagger_window_open·_closed / execution_performed
        ▼
    flag_changed(key, old, new) → [Rank-1] hud.gd / impact_feedback.gd 抉择·处决 HUD 增量刷新（消费呈现、不写 flag）
        │
        ▼
    delta.json（磁盘唯一权威）── 新进程 load ──▶ _apply_snapshot ──▶ get_flag 读回（三态验证）
```

- **写入唯一性**：A44 `encounter_director.gd` 唯一写入方 = Rank-1；Rank-3 只登记口径 + 只读验证脚本；Rank-2 表/服务纯逻辑；Rank-1 HUD/反馈只读呈现。
- **顺序不变量**：先 `commit` 落盘、后改运行时实例 / `emit flag_changed`；落盘失败不推进、如实告警。
- **`--script` 模式纪律**：验证脚本 `extends SceneTree` + `_initialize()`，用 `Engine.get_main_loop() as SceneTree` 取 root 相对探活，**不用 `get_tree()`、不用 `/root/...` 绝对路径**；资源回读 `CACHE_MODE_IGNORE`；三进程独立 PID 临时槽 `user://saves/verify_v100_<RUN>/`，与生产 `slot_01` 物理隔离。

## 9. 风险、假设与回滚方案

- **并发写入**：本轮四路并发，`encounter_director.gd` 唯一写入方 Rank-1（A44）；Rank-3 全部读写落在独立临时槽 `user://saves/verify_v100_<RUN>/`，对生产 `slot_01` 只做 `get_md5` 只读前后对照，避免共享 `delta.json` 造成回归抖动（R27/R31 先例）。
- **`--script` 模式**：手动 `new()` 的 WorldState 不进场景树、`add_child` 不自动 flush `_ready()`，一律显式 `call("_ready")`；探活走 `Engine.get_main_loop() as SceneTree` 相对路径，不用 `get_tree()` / `/root/...`。
- **「新进程 load」等价口径（如实登记、不伪造）**：`world_state.gd::_load()` 的 `DELTA_PATH` 常量写死生产 `slot_01`，「不碰生产存档」约束下不能把测试快照写进生产槽；`_load()` 对 `schema_version=3` 且无 `delta.log` 的干净 delta 的实质动作是 `_migrate()`（恒等）→ `_replay_log([])`（恒等）→ `_apply_snapshot(state)`，故三态验证改走「自读独立槽 `delta.json` → 新建 WorldState → `_apply_snapshot`」，语义等价于 `_load()` 注入段、数据源指向独立槽。列为待总指挥裁决项（见 `DONE-R32.md`）。
- **JSON int→float**：`JSON.parse_string` 把 int 读回为 float（日志 `performed=3.0` / `schema_version=3.0`），由 `_val_eq` / `int()` 容忍，不影响三段式正则 / 类型 / 余额判定，如实登记不隐藏。
- **`[PLACEHOLDER]` 数值**：夹具 `1000 / 600 / 400 / boon_frost_edge / 3` 只用于确定性三态回读、非设计数值；试玩校准后需同步迭代文档 / 验证脚本 `FIX_*` 常量 / DONE / 数据表，不静默改数。
- **回滚**：① 删除 `verify_v100_save_readback.gd`、迭代文档、两份 DONE、两份回执；② 契约 §3.3 只撤 R32 说明段、存档规范 §3.3 只撤 4 行 + R32 注记、README 只撤 v0.10.0 追加段（历史行逐字保留）；③ 重跑 `--import` + `--check-only --script` + `--quit` 确认 `SCRIPT ERROR=0`、既有 31 PASS 存档/HUD 回归不回退、`courtyard.tscn node_count=41` 不变。**不触碰任何 `godot/` 业务代码与其它 Rank 产出**。
