## 1. 核心循环诊断（Game Designer）

v0.3.0 的循环只有「翻滚躲 → 攻击 → 击败一次 Boss → 胜利落盘 → 赐福休息重打」。诊断出的四个断点：

| 断点 | 表现 | 本版补法 |
|---|---|---|
| 无目标梯度 | 只有一个「击败一次」目标 | 三波试炼：30 秒短期 / 一局三波中期 / 最高波次长期 |
| 无成长正反馈 | 胜利只写 flag，没有奖励 | 每波赐福点数 100/150/200，HUD 实时跳动 |
| 无探索/入场回报 | 庭院静态、敌人突然开打 | 1.5s 入场预告 + 波次 HUD + 敌人可见站位 |
| 前 30 秒无引导 | 玩家不知道要做什么 | 自动开始 + 「第 N/3 波｜倒计时｜历史最佳」常驻提示 |

## 2. 玩法拆解表（所有数值标 `[PLACEHOLDER]` 待人工试玩校准）

| 需求点 | 映射机制 | 关键数值 | 状态依赖 | 验收现象 |
|---|---|---|---|---|
| 短期目标 | 当前波击杀 + 30 秒倒计时 | 3 波 / 每波 30s | `wave_index` / timer | HUD「第 N/3 波」 |
| 正反馈 | 赐福点数 + 波次推进 | 每波 +100/150/200 | `grace.trial.points` | 击杀瞬间点数增加 |
| 中期目标 | 三波全清 | 3 波 | `dungeon.wave_trial.completed` | 「试炼完成」+ 落盘 |
| 长期钩子 | 最高波次存档 | `dungeon.wave_trial.best_wave` | WorldState flag | 重开显示历史最佳 |
| 难度曲线 | 血量倍率/敌人/站位变化 | 1.0 / 1.3 / 1.6 | `wave_trial.tres` | 三波耗时递增不卡关 |
| 关卡节奏 | 入场读秒 + 可见预告 + 退避空间 | telegraph 1.5s | TELEGRAPH 状态 | 敌人出现前有预告 |

**broken 定义**（`WAVE-TRIAL-TUNING.md`）：B1 首波 30 秒打不完=难度过高；B2 三波全清 <15 秒=难度过低；B3 点数通胀=奖励失衡。数值假设表与调参唯一入口 `.tres → verify EXPECT_* → 文档` 三处同步。

## 4. 调度中枢：第三次重启与根因

- 派单前 `/api/state` 第三次 502（进程退出）。按既有授权 `--headless` 后台拉起 `dist/AierdengfahuanCommander.exe`，`POST /api/config` 恢复 `space=teamwork/command_center` / `demo=false` / `poll_ms=600` / 4 路钩子，复核 `96/96 done` 后才派单。
- **根因（如实）**：后台任务随 WorkBuddy 会话/轮次结束被清理，导致跨轮进程退出；工具限制不允许 detached 常驻。若需长期常驻，需用户手动双击 exe 或明确授权常驻启动方式。在此之前的每次重启都必须先恢复配置并核验 `space` 与 `demo`。
