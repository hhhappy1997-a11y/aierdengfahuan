## 2. I-2（2 → 3）：击败事件信号（2 号是提供方）

### 2.1 对外信号总表

| 信号 | 参数 | 发射时机 | 订阅方 | 契约 |
|---|---|---|---|---|
| `enemy_defeated` | `enemy_id: String` | 普通 / 精英敌人 HP 归零，死亡演出开始前 | 3 号（写 Delta） | I-2 |
| `boss_defeated` | `boss_id: String` | Boss HP 归零，死亡演出开始前 | 3 号（写 Delta） | I-2 |
| `state_changed` | `from_state: State, to_state: State` | 玩家状态转移完成 | 1 号（可选，做镜头 / 特效）、UI | 模块内 |
| `invulnerability_changed` | `active: bool` | 无敌窗口进入 / 离开 | UI（可选提示）、1 号（可选残影） | 模块内 |
| `damage_dealt` | `target_id: String, amount: float, damage_type: String` | 伤害结算完成 | UI（伤害数字）、1 号（命中特效） | 模块内 |
| `poise_damage_dealt` | `target_id: String, amount: float` | 削韧结算完成 | UI（韧性条） | 模块内 |
| `status_buildup_applied` | `target_id: String, status_type: String, amount: float` | 异常积累累加后 | UI（异常槽） | 模块内 |
| `stance_broken` | `target_id: String` | 目标韧性归零 | UI（处决提示） | 模块内 |
| `death_confirmed` | 无 | 玩家进入 `DEATH` 状态 | 3 号 / 1 号（可选） | 模块内 |

> `State` 枚举定义在 `player_state_machine.gd`（`IDLE/WALK/RUN/ROLL/ATTACK_LIGHT/ATTACK_HEAVY/HITSTUN/DEATH`），订阅方按整数或同名枚举使用。

### 2.2 谁通知谁（信号流）

```
[玩家 / 敌人攻击命中]
   → CombatResolver（2 号，M1/M5 落地）
       ├ 计算伤害 / 削韧 / 异常积累  → damage_dealt / poise_damage_dealt / status_buildup_applied
       ├ 目标韧性 <= 0              → stance_broken
       └ 目标 HP <= 0
            → PlayerStateMachine.report_defeat(instance_id, is_boss)   ← 全模块唯一发射点
                 ├ enemy_defeated(enemy_id) ──────→ 3 号订阅 → 写 SaveDelta（I-2）
                 └ boss_defeated(boss_id)  ──────→ 3 号订阅 → 写 SaveDelta（I-2）
```

**参数取值约定**：`enemy_id` / `boss_id` 优先取 `SpawnRequest.enemy_instance_id`（实例唯一）；请求缺省时回退 `EnemyData.id` / `BossData.id`（如 `boss_01_margit`）。3 号不得假设 id 一定带实例后缀。

**边界**：2 号不 `set_flag("...defeated", true)`、不自行复活实体；`respawn_on_rest` 由 3 号 Delta 决定（I-3 字段）。

### 2.3 对外方法总表（`PlayerStateMachine`）

| 方法 | 签名 | 用途 | 调用方 |
|---|---|---|---|
| `request_state` | `(next_state: State) -> bool` | 请求状态转移（含优先级 / 白名单判定） | 玩家输入层（1 号 / 主 AI） |
| `is_invulnerable` | `() -> bool` | 查询当前帧是否无敌 | 伤害结算 |
| `is_in_hit_window` | `() -> bool` | 查询是否处于攻击判定帧 | 命中检测 |
| `register_hit` | `(target_id: String) -> bool` | 同一动作对同一目标去重 | 命中检测 |
| `frame_to_seconds` | `(action: PlayerActionData, frames: int) -> float` | 帧→秒换算（按 `logic_fps`） | UI / 日志 |
| `compute_damage` | `(A, M, P, S, D: float) -> float` | 纯函数伤害公式（5 入参全来自数据表） | 战斗结算 |
| `compute_effective_status_threshold` | `(buildup, accumulated_resistance, phase_multiplier) -> float` | 有效异常阈值 | 异常结算 |
| `compute_status_trigger_damage` | `(buildup, target_max_hp) -> float` | 异常触发伤害 | 异常结算 |
| `report_defeat` | `(instance_id: String, is_boss: bool) -> void` | **I-2 唯一发射点** | Boss / 敌人击杀结算 |
| `emit_damage` / `emit_poise_damage` | 见代码 | 转发结算信号 | 战斗结算 |

## 3. I-3（3 → 2）：消费 `SpawnRequest`

| 项 | 内容 |
|---|---|
| 消费入口 | `EnemyDirector.spawn_from_request(request: SpawnRequest)`（M1 工程落地，本轮只定契约） |
| 字段真源 | **3 号定义**；`数据表schema.md` §8 是 2 号消费侧最小字段假设，不是定义权声明 |
| 2 号读的字段 | `request_id`、`enemy_data_path`、`enemy_instance_id`、`spawn_position`(Vector3)、`spawn_facing_deg`、`chunk_id`、`is_boss`、`respawn_on_rest`、`level_offset`、`initial_flags` |
| 2 号透传 | `chunk_id` → 1 号做流式加载归属；2 号不管理 chunk、不 load/unload 场景 |
| 2 号只读 | `initial_flags`（3 号给的 flag 快照），不回写 |
| 去重 | 相同 `request_id` 直接丢弃，避免 chunk 重复加载时刷出双份敌人（M2） |
| 分支 | `is_boss == true` → 挂 `PhaseTransition`；`false` → 普通追击 AI |
| 击败回传 | `report_defeat(request.enemy_instance_id, request.is_boss)` → I-2 |
| 立场 | Boss 与已击败实体应为 `respawn_on_rest = false`；是否复活完全由 3 号 Delta 决定 |

**对 3 号的依赖**：`SpawnRequest` 最终字段表与脚本路径、`enemy_instance_id` 是否必填、`initial_flags` 的 key 命名、Autoload 名称。

## 4. I-4（1 → 2）：只调 `set_pose(pose_name, frame_index)`

| 项 | 内容 |
|---|---|
| 唯一调用点 | `player_state_machine.gd::_apply_pose()` |
| 调用形式 | `_sprite.call("set_pose", action.pose_name, action.pose_frame_offset + state_frame)`，先 `has_method("set_pose")` 判空 |
| 节点路径 | `@export var sprite_path: NodePath = ^"../Hybrid2D3DAnimatedSprite"`（可在编辑器改，不写死节点类） |
| pose 名来源 | `PlayerActionData.pose_name`（玩家 8 个：`idle/walk/run/roll/attack_light/attack_heavy/hitstun/death`）；Boss 侧为 `PhaseData.pose_prefix + MoveData.pose_name`（如 `p2_holy_hammer`）；异常 / 崩坏 pose 来自 `StatusBuildup.trigger_pose_name` / `PoiseConfig.poise_break_pose_name` |
| frame_index | 动作内帧号 = `pose_frame_offset + state_frame`，从 0 递增；**语义待裁决（Q4）**：需 1 号确认是「动作内帧索引」还是「SpriteFrames 全局帧索引」，以及由谁 clamp 到实际帧数 |
| 明确不做 | 不写 billboard、底部中心锚定、像素→米缩放、自定义 AABB、`SpriteFrames` 赋值、`texture_filter`、光照、后处理 —— 全部归 1 号 |

**阶段切换的已知冲突（Q1）**：总纲 3.4 要求「替换 `SpriteFrames` 资源」，但 I-4 只约定 `set_pose` 一个方法。本轮**不私改契约**：
- 数据侧保留 `PhaseData.sprite_frames_path`（登记两个阶段的精灵表路径，本轮不调用）；
- 运行侧用 `pose_prefix`（`p1_` / `p2_`）让 1 号的同一套 `SpriteFrames` 预置两组 pose，`set_pose("p2_holy_hammer", frame)` 即可切阶段动画，**零接口扩展、改数据表不改代码**；
- 若主 AI 裁决必须真正替换 `SpriteFrames`，需 1 号新增入口，见 `README.md` Q1。

### 4.1 对外可见的资源字段（1 号 / 3 号需要知道的）

| 字段 | 所属类 | 消费方 | 用途 |
|---|---|---|---|
| `pose_name` | `PlayerActionData` / `MoveData` | 1 号 | `set_pose` 第一参数 |
| `pose_prefix` | `PhaseData` / `EnemyData` | 1 号 | 拼 pose 名，区分阶段 / 敌种 |
| `pose_frame_offset` | `PlayerActionData` | 1 号 | `set_pose` 第二参数基准 |
| `transition_pose_name` / `transition_frames` | `PhaseData` | 1 号 | 转阶段演出 |
| `trigger_pose_name` / `poise_break_pose_name` / `death_pose_name` | `StatusBuildup` / `PoiseConfig` / `BossData` | 1 号 | 异常 / 崩坏 / 死亡演出 |
| `sprite_frames_path` | `PhaseData` | 1 号（**本轮仅登记**） | Q1 裁决后可能启用 |
| `defeated_flag_key` | `BossData` / `EnemyData` | 3 号 | 三段式 flag key，2 号只读 |
| `id` | `BossData` / `EnemyData` | 3 号 | `boss_defeated` / `enemy_defeated` 的参数回退值 |
| `chunk_id` | `SpawnRequest` | 1 号 | 流式加载归属（2 号透传） |
| `phase_thresholds` / `hp_ratio_exit` | `BossData` / `PhaseData` | 主 AI | 「改数值不改代码」验收点 |
