# 艾尔登法环像素游戏——Godot 2.5D 技术规划（总纲 v1.0）

> 本文件是 5-AI 协作的**唯一需求源**。1~4 号执行 AI 必须先读本文件与 `00-协作契约.md`。
> 来源：用户整合多轮讨论后的完整规划。核心变化：驱动层从 Godogen 切换为 WorkBuddy，美术层用 ComfyUI 自建像素管线；Godogen 的 HD-2D 架构思路和法环 Boss 数据保留，作为项目骨架与战斗系统基础。

---

## 0. 项目定位

用 **Godot 4 + WorkBuddy（驱动）+ ComfyUI（美术）** 制作一款 2.5D HD-2D 像素风格的法环同人游戏。不做交界地 1:1 复刻，而是把法环的**纵深地形、赐福网络、箱庭地牢、数据驱动 Boss 战**翻译成像素语言。路线选 **HD-2D**：3D 地形 + 2D 像素角色，这是像素约束下唯一能保留"黄金树光照"和"悬崖纵深"的方案。

## 1. 驱动层：WorkBuddy 替代 Godogen

### 为什么换

Godogen 是"一句话生成完整 Godot 工程"的自主流水线，但它生成的美术不可控，复杂动作和法环审美需要人工兜底。WorkBuddy 的定位更适合长期迭代的项目：

- **本地读写不烧 token**：文件解析、目录遍历、内容预处理全部在本机完成，只把需要推理的精简结构提交模型。高强度跑半小时逻辑校验仅消耗几十积分，成本远低于全量上传上下文的 Agent。
- **长上下文锁定工程架构**：搭载 Hy3 / Step-5-Preview 模型，可以一次性吃透整套 Godot 工程脚本，全局排查逻辑漏洞、数值冲突、时序 bug，且不会私自改接口、改变量。
- **Godot MCP 直连**：通过 `@coding-solo/godot-mcp` 让 WorkBuddy 直接操作 Godot 场景和节点，而不是只生成代码片段。
- **专家角色 + 工作流**：WorkBuddy 内置预设专家 Prompt（如"节点通"负责 GDScript），可以按任务切换角色，而不是一个通用 Agent 硬扛所有环节。

### 安装与配置

1. Godot 4（标准版，GDScript）加入 PATH。
2. 安装 WorkBuddy，在链接器中配置 Godot MCP：

```json
{
  "mcpServers": {
    "godot": {
      "command": "npx",
      "args": ["@coding-solo/godot-mcp"],
      "env": { "DEBUG": "true" },
      "disabled": false
    }
  }
}
```

3. 在 WorkBuddy 中选择"节点通"（Godot 脚本工程师）或"游戏逻辑"类专家，把项目说明书（规则/数据表/决策记录）喂进去，作为长期约束。

### WorkBuddy 的使用边界

- **让它做**：场景树搭建、GDScript 编写、逻辑校验、数值冲突排查、MCP 驱动 Godot 操作、重构。
- **不要让它做**：像素美术的最终审美决策、Boss 招式的"手感"调校、关卡密度的设计判断。这些必须人工兜底，WorkBuddy 只做底稿和结构化辅助。

## 2. 美术层：ComfyUI 像素管线

### 2.1 核心工作流：单图 → 多帧精灵表

使用 **comfyui-2d-character-pipeline** 的思路：输入一张角色基准图，自动输出分层动画精灵表。

**两条管线**：

- **管线 1（基础动画）**：角色图 → W1 姿态编辑（Qwen-Image-Edit）→ W2 图生视频 → W3 精灵表拼接。产出 idle、walk、jump 等基础动画的横向等尺寸帧条。
- **管线 2（装饰分层）**：基础视频 + 装饰参考图 → W4 局部重绘 → W5 装饰精灵表。头发、眼睛、衣物作为独立 RGBA 层，与基础动画**逐像素对齐**，运行时叠加无需重新校准。

这套管线以 **API JSON 格式**分发，可由 AI Agent 自动调用，不依赖手动拖节点图。

### 2.2 像素风格的锁定

在通用管线基础上叠加像素控制：

- **LoRA**：使用 `Limbicnation/pixel-art-lora` 固定像素画风，触发词写入正向提示词。
- **ControlNet OpenPose**：锁定角色姿态，保证同一动作在不同角色间一致。
- **LayerDiffuse**：直接生成透明底 RGBA，省掉抠图。
- **降采样 + 人工精修**：AI 输出高清图 → ImageMagick 降至目标像素分辨率 → Aseprite 手工修帧。AI 负责"量"（杂兵、道具、环境），人工负责"魂"（主角、Boss、关键场景）。

### 2.3 风格一致性控制

法环同人最怕"每张图风格漂移"。用三层约束：

1. **IP-Adapter + LoRA + ControlNet 组合**：批量生成时锁定风格、结构和姿态。
2. **固定 Prompt 骨架**：只替换 `[SUBJECT]`，风格、光照、调色板描述保持不变。
3. **种子锁定（可选）**：同一 seed 跨 prompt 使用，维持风格稳定性。

### 2.4 从 ComfyUI 到 Godot 的落地

- 产物落到 Godot 项目的 `assets/generated/<品类>/`，并给出 `res://` 路径。**godot-imagegen** 插件可以把 ComfyUI 内嵌进工作流，对话中直接出图、改写工作流、产物自动注册进资产库。
- Godot 导入设置：像素图 → **lossless、关闭 mipmaps、`texture_filter` 设为 nearest**，项目级 `default_texture_filter=0`。
- 如果需要视频转精灵表，有现成的 ComfyUI 节点可以把视频直接转成 Godot 可直接使用的 spritesheet 文件。

### 2.5 ComfyUI 的定位

ComfyUI 负责**像素美术的产能**，不负责"一键产出成品"。Boss 的多阶段动画、主角的翻滚/攻击帧、关键场景的构图，仍然需要在 Aseprite 中精修。ComfyUI 的价值是把"从零画一帧"变成"从底稿改一帧"，把迭代周期从小时级压到分钟级。

## 3. Godot 项目架构

### 3.1 2.5D 渲染方案

- **角色**：使用 **Hybrid2D3D-Renderer** GDExtension 的 `Hybrid2D3DSprite` / `Hybrid2D3DAnimatedSprite`。它解决 HD-2D 的三个核心问题：像素→米自动缩放、底部中心锚定（脚贴地）、自定义 AABB 防止屏幕边缘消失。状态机里可以 `set_pose("roll", 2)` 强制锁定帧。
- **地形**：3D 网格搭建，不用 TileMap，才能做悬崖、高低差、地下入口。
- **像素化后处理**：Camera3D 前加全屏低分辨率渲染 + Nearest 放大 shader，保持像素颗粒感。
- **光照**：DirectionalLight3D + 环境光，暖黄主光配冷色阴影，这是"黄金树氛围"的核心。

### 3.2 大地图：分块流式加载

法环不是无缝平面，而是**开放区域 + 箱庭地牢 + 地下世界**的分层结构。

- **区块流式加载**：根据玩家位置 `ResourceLoader.load_threaded_request()` 异步 load/unload，用 **Delta 持久化**只记录变化状态（已开宝箱、已杀 Boss、已点赐福）。
- **区域边界藏在视线阻断处**：悬崖、升降机、地道作为加载边界，玩家感知不到。
- **密度优先于尺寸**：每 30 秒路程内必须有 POI（赐福、地牢入口、精英敌人、NPC）。像素风格下空大地图的负反馈会被放大。
- **箱庭地牢独立场景**：短加载进入，多层立体结构 + 捷径 + 单向门。这是法环的灵魂，2.5D 像素下比大地表更容易做出"魂味"。

### 3.3 RPG 交互

- **对话**：Resource 驱动（`DialogueLine` + `DialogueChoice`），条件门控检查 flag 和背包。赐福处的"交谈/回忆"复用同一套系统，只换触发源。
- **任务**：信号 + 状态机，任务定义是 Resource（id / 阶段 / 前置 flag / 奖励），存档只存任务 id + 当前阶段 + flag 集合。
- **拾取/门/隐藏墙**：Area3D + 提示图标 + Delta 持久化。隐藏墙不做任何提示。

### 3.4 战斗系统：数据驱动

把前几轮整理的 Boss 数据（削韧、异常积累、阶段阈值、招式倍率）存成 **Resource 数据表**，战斗运行时查表结算。Boss 多阶段 = 状态机里的 `PhaseTransition` 状态 + 替换 `SpriteFrames` 资源 + 切换攻击表，不换整个场景。

## 4. 整合后的里程碑

| 阶段 | 内容 | 驱动工具 | 验收标准 |
|---|---|---|---|
| **M0 管线验证** | WorkBuddy + Godot MCP 连通；ComfyUI 生成 1 个 32px 像素角色 idle+walk 精灵表，导入 Godot 用 Hybrid2D3D 渲染 | WorkBuddy / ComfyUI | 角色脚贴地、像素清晰、无 z-fighting |
| **M1 垂直切片** | 3D 庭院 + 移动/翻滚/轻攻击 + 1 个会追击的敌人；WorkBuddy 通过 MCP 搭场景树 | WorkBuddy | 手感可玩，翻滚无敌帧正确 |
| **M2 流式加载** | 3 个相邻小区域 chunk streaming，往返走不重复加载、无帧卡顿 | WorkBuddy | 性能监视器无 spike |
| **M3 首个箱庭** | 独立地牢场景，多层 + 1 条单向门捷径 + 1 个赐福 + 1 个精英敌人 | WorkBuddy | Delta 持久化正确，短加载正常 |
| **M4 RPG 层** | 对话图 + 任务状态机 + 拾取 + 赐福菜单，1 个 NPC 任务闭环 | WorkBuddy | flag 变化驱动对话分支 |
| **M5 Boss 骨架** | 选"恶兆妖鬼"或"接肢"葛瑞克，Resource 数据驱动二阶段 + 2—3 个核心招式 | WorkBuddy / ComfyUI | 数据表改数值不改代码 |
| **M6 拼接** | 3—4 区域 + 2 地牢 + 1 地下入口，赐福传送网络 | WorkBuddy | 可完整跑通一条探索线 |

## 5. 风险与规避

1. **ComfyUI 风格漂移**：三层约束（IP-Adapter+LoRA+ControlNet、固定 Prompt 骨架、种子锁定）必须从第一天就搭好，不要后期补救。
2. **WorkBuddy 的"审美盲区"**：它能校验逻辑和数值，但发现不了"这个 Boss 招式不公平""这个区域太空"。**每个里程碑必须自己上手玩**。
3. **Hybrid2D3D 的脚贴地和遮挡排序**：直接用现成插件，不要自己从头写 billboard 和锚定逻辑，这是 HD-2D 最容易翻车的地方。
4. **大地图尺寸冲动**：先做密度再做广度。一个做满的宁姆格福 > 一个空荡荡的整个交界地。

## 6. 待确认

- **ComfyUI 硬件**：2D 角色管线设计为 **24GB VRAM**（RTX 3090 级），峰值约 22.5GB。如果本地显存不足，需要考虑云 ComfyUI 或降低管线规格（如跳过图生视频环节，直接用单帧 + 手工补帧）。这是整合后最需要先确认的硬性约束。
- **WorkBuddy 的 Godot MCP 兼容性**：不同版本的 `@coding-solo/godot-mcp` 对 Godot 4.x 小版本的支持可能有差异，M0 阶段先验证"WorkBuddy 能通过 MCP 在 Godot 里创建/修改节点"再继续。
