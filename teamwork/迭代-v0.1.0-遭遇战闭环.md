# 迭代 v0.1.0 · 单次遭遇战可玩闭环

> 版本 v0.1.0 ｜ 2026-11-09 ｜ 引擎 Godot 4.7.2.stable（GDScript） ｜ 工程 `F:/Game/aierdengfahuan/godot`
> 里程碑：把已有战斗数据/系统接成「输入 → 判定 → 结算 → 落盘」一条可验证闭环
> 官方依据：docs.godotengine.org/en/stable/classes/class_node.html、class_refcounted.html、class_packedscene.html（适用 Godot 4.x；3.x 的 `KinematicBody`/`Spatial`/`yield` 均不涉及）

## 1. 玩法拆解表

| 需求点 | 映射机制 | 关键数值（默认，可调位置） | 状态依赖 | 验收现象 |
|---|---|---|---|---|
| 玩家想「躲开 Boss 攻击」 | 翻滚动作三段帧 + 无敌窗口 | `roll 4/9/9=22 帧@60`、无敌 `[4,13)`；来源 `data/combat/player_actions.tres` | PlayerActionState 帧计数 | 第 4/12 帧受击免伤（HP 不变、闪避 +1），第 3/13 帧正常扣血 |
| 玩家想「打掉 Boss 血」 | 攻击 active 首帧命中 → CombatResolver.compute_damage → BossController.apply_damage | `base_attack` / `motion_multiplier` / `base_defense`；`MIN_DAMAGE=1` | 动作 active 窗口、Boss 阶段 | 命中 1 次 Boss HP 比例 1.0 → 0.9877，`hits_landed=1` |
| 玩家想「输了能重来」 | 赐福休息重置 HP 与状态机 + 强制落盘 | `player_max_hp=100`（导演层 `@export`）、`incoming_damage=12` | 结算态 outcome | HP 0 → 休息回 100、outcome 回 -1、commit 一次 |
| 击杀要有永久结果 | I-2：BossController._die → CombatEventBus → GameEvents → SaveDeltaWriter | flag `combat.<boss_id>.defeated` | 三段式 flag 正则 | `WorldState.get_flag` 返回 true |
| 连点/同帧重复不能刷伤害 | 忙时拒绝 request + active 首帧单次结算 | `state_priority` 未用；`_last_attack_id` 去重 | PlayerActionState.busy | 忙时第二次 request 返回 false，同动作只结算 1 次 |

## 4. 架构与节点清单

```
EncounterRoot (Node)                      ← encounter_director.gd（新增，统一驱动）
├── Boss (Node3D)                          ← boss_controller.gd（复用，set_physics_process(false)）
├── CombatEventBus (Node)                  ← combat_event_bus.gd（复用，I-2 唯一发射点）
├── CombatResolver (Node)                  ← combat_resolver.gd（复用，compute_damage）
└── HUD (CanvasLayer, layer=20)
    └── StatusLabel (Label)                ← 只读显示 HP/阶段/帧/结算
```

- **谁持有状态**：导演层持玩家 HP / outcome / 计数；`PlayerActionState` 持动作帧；BossController 持 Boss HP 与阶段；WorldState 持 flag。
- **谁驱动**：`EncounterDirector._physics_process` 每拍调 `_step(delta)` → 状态机 tick → 玩家命中判定 → `BossController.advance(delta)` → HUD。固定 60 拍与 `logic_fps=60` 对齐，不用 delta 累加帧。
- **数据流**：`_unhandled_input` → `request(pose)` → 帧窗口 → `move_landed`（免伤/扣血）或 `apply_damage`（Boss 掉血）→ `_die` → `report_defeat` → `GameEvents.boss_defeated` → `SaveDeltaWriter._on_boss_defeated` → `combat.<id>.defeated` + `commit`。
- **失败降级**：Boss / Resolver / SaveDeltaWriter / table 任一缺失 → `push_warning` 并继续可测；`CombatResolver.compute_damage` 缺失时按同式 `max(1, A×M−D)` 直算；信号连接在 `_exit_tree` 断开。
- **怎么验证**：`build_encounter_v010.gd` 生成并 `CACHE_MODE_IGNORE` 回读；`verify_encounter_v010.gd` 断言；`--quit-after 90 res://scenes/encounter_v010.tscn` 跑 L3 主循环。

## 6. 自测与问题定位闭环（发现 → 定位 → 修复 → 验证）

| # | 现象 | 根因 | 修复 | 验证 |

| 2 | 集成层 10 条断言全 FAIL、快照全是初始值 | `extends SceneTree` 的 `--script` 模式下 `add_child` 不 flush `_ready()` | 按项目既有验证惯例显式 `call("_ready")` | `init_hp_full` 等 9 条转 PASS |

**最终自测**：`SUMMARY pass=20 fail=0 RESULT=ALL_MATCH`、EXIT=0、`SCRIPT ERROR=0`。
**三段门禁**：`--headless --import` EXIT=0；4 个新脚本 `--check-only --script` 全 EXIT=0；`--headless --quit` EXIT=0；全量日志 `SCRIPT ERROR/Parse Error` 合计 **0**。

## 8. 风险、存档影响与回滚

- **存档影响（如实）**：自测经真实 I-2 链调用 `SaveDeltaWriter.commit()`，会向 `user://saves/slot_01/` 写一条 `boss_defeated` delta；测试结束已把 `world.boss_01_margit.defeated` 与 `combat.boss_01_margit.defeated` 两个内存 flag 恢复为原值，磁盘日志保留该条记录。`BossController` 读的是 `world.*` 就绪 key，不受影响。
- **未覆盖**：削韧/异常状态、Boss 重置、招式冷却、L4 泄漏曲线、真机移动端、人工手感。
- **`--script` 模式绝对路径限制**：仅影响验证脚本，不影响运行时；若后续要把它根除，需要改既有件（超出本版范围，需另行授权）。
- **回滚方案**：删除 `scenes/encounter_v010.tscn` 与 4 个 `scripts/combat/*v010*|player_action_state|encounter_director` 新文件即可回到上一版；`project.godot`、`courtyard.tscn`、`Main.tscn`、所有既有战斗件与数据表**零改动**，无需回滚配置。回滚后重跑 `--headless --import` + `--headless --quit` 确认 `SCRIPT ERROR=0`。
