## 3. GDD 六项（game-development-pro：purpose / player experience goal / inputs / outputs / edge cases / failure states）

### 3.1 元素瓶（A70）

| 项 | 内容 |
|---|---|
| **purpose** | 给玩家一个可自主管理的「有限次数恢复资源」，把「HP 管理」从纯被动受击变成主动决策；补齐「行动→反馈→目标→消费成长」循环里的生存维度，且把该资源状态持久化。 |
| **player experience goal** | 15~20 秒实机里肉眼可见「元素瓶 3/3 → 2/3」递减、血条补间、「瓶数不足 / 生命已满」即时反馈、赐福 / 重生回满 3/3 的安心感；重启后瓶数状态一致。 |
| **inputs** | `G`(71) 按键（HUD + ENC 双接、event 实例幂等去重）；`flask_rules.tres` 4 字段；`use_flask(current_hp, max_hp)` 生产驱动口；`flask_used / flask_rejected / flask_restored` 3 信号。 |
| **outputs** | HUD `ProdFlaskLabel`「元素瓶 N/M」+ 血条；磁盘 5 个 `combat.flask.*` flag；`flask_used` 的 `hp_after` 由 ENC 原样写回真实 `_player_hp`（A57）。 |
| **edge cases** | 瓶尽 / 满血 / 相邻同签名重复按键 / 异常 HP（null / NaN / Inf / 负 / 超上限）/ config 缺失 / 非法表 / 回满超上限封顶 / 死亡期间 G 被门禁拒绝；拒绝一律不改状态、不写盘。 |
| **failure states** | 规则表不可用 → `push_warning` 降级、元素瓶不可使用、不崩；commit 失败 → 磁盘未改、运行时实例保持旧值、如实告警；拒绝事件 → HUD 反馈 + 编排层观测，不产生 commit。 |
