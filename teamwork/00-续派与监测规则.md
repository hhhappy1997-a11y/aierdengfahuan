## 2. 完成判据（最小侵入，不扫全目录）

- 每一轮 `R<N>` 派单，执行 AI 完成后在**自己工位内**写 `DONE-R<N>.md`，内容含：① 实际交付文件清单；② 自检结果（含真跑输出结论）；③ 未完成项与阻塞。
- 监测**只检查 4 个 `DONE-R<N>.md` 是否存在**，不遍历设计文档、不读正文推断进度、不写探针 / 测量 / preflight 脚本。
- `DONE-R<N>.md` 不存在 = 该路未完成，继续等待，不催促、不刷屏。
- 首轮 R1 无 `DONE-R1.md`，其完成由「4 路交付件齐全 + 各自 README 交付清单自检」确认，已记入 `00-进度台账.md` §2。

## 3. 任务池来源（按优先级，全部来自 teamwork 文件）

1. 各工位 `README.md` §4「未完成项」与 §6「可做的更新方向 / 建议下一步」—— **最高优先，直接转写为下一轮任务书**
2. 各工位 `接口契约.md` §6「本模块 M0~M6 交付表」
3. `00-项目总纲.md` §4 里程碑 M0~M6 的验收标准

> 依赖总指挥裁决的项（各 README 的「待主 AI 裁决项」）**不派发为独立任务**；只在任务书里给「本轮临时执行口径」，让各路不被阻塞，并注明「裁决后按裁决回改」。

## 4. 续派流程（发现完成即自动执行）

1. 读本规则 + `00-进度台账.md`，确定当前轮次与 4 路状态。
2. 检查 4 个 `DONE-R<N>.md`，列出本轮新完成的工位。
3. **只给新完成的工位**生成 `任务书-R<N+1>.md`（不覆盖历史任务书，保留 git 可回溯）。
4. 任务书必须自包含：唯一可写目录、交付清单（文件名固定）、硬性约束、真跑要求、`DONE-R<N+1>.md` 完成标志。
5. 在 `00-群聊总线.md` 末尾追加**一条** `HOST → ALL` 派单通知（append-only，不刷屏）。
6. 更新 `00-进度台账.md`：§2 状态、§3 来件（如有）、§7 变更记录、§9 仓库产物记录。
7. `git add` → `git commit` → `git push`；失败如实记录、不谎报、下次重试（契约 §9.1 / 台账 §8）。
8. **无新完成标志 → 不改任何文件、不 push、静默结束**。

## 5. 监测节奏与「不刺探」的关系

- 用户本次明确要求「实时监测」，构成契约 §5「只有用户明确说刺探 / 巡检才做一次只读检查」的**授权**。
- 落地方式：平台定时任务每小时巡检一次（系统最细调度粒度为 1 小时）；每次只做 §2 的完成标志检查。
- **该授权只适用于 HOST 助理的调度监测**。4 个执行 AI 仍严格遵守契约 §5 与 `00-群组通信协议.md` §3：开工只读一次总线、不扫别人工位、不轮询、不写探针。
- 用户可随时说「停掉自动监测」或「改事件驱动」；总指挥回来后以总指挥口径为准。
